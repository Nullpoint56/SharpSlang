# SharpSlang: working notes

For coding agents and contributors: what the repository is, its rules, how to build and test, the
patch process, the decisions, and the Slang behaviour the binding is built around. Usage for
library users is in `docs/guide.md`; every Slang defect, with its report text and whether the
packaged compiler carries a fix, is in `docs/upstream.md` (the registry, `docs/upstream.json`).
History (how a finding was reached, earlier figures, earlier pins) is in git log.

These notes describe the pinned Slang release, `<SlangVersion>` in `Directory.Build.props`. A
caveat below states Slang's own behaviour and names its defect (U and a number); whether the
packaged compiler fixes it is the registry's to say, not these notes'. A figure stated here names
how it was measured; a test that pins one reads this file (`DocumentedFactsTests.Documents`).

---

## The repository

C# binding over the Slang shader compiler, plus opt-in shader pipeline packages built on the
binding's public API. One release pins exactly one Slang release (an exact pin, not a floor): Slang
states its public ABI is not stable and directs redistributors to ship the libraries they built
against. .NET 11 / C# 15, xunit.v3 on Microsoft.Testing.Platform.

### Branches

- `master` is the default and only long-lived branch, pinned to the latest Slang tag; releases are
  cut from it. A future `next` would pin a commit of Slang's `master`, with binding work merged
  forward and L0 regenerated there.
- **Adopting a tag**: point `slang/` at it (`git update-index --cacheinfo 160000,<commit>,slang`,
  the one sanctioned way to stage the pointer), set `<SlangVersion>`, run the Slang-bump check
  (Patches), re-cut the patches that still apply, regenerate L0, run Windows and WSL on fresh build
  trees, and re-measure the figures these notes state.

### Layers

```
L3  dotnet/Extensions/   one class per optional Slang interface, acquired on first use (TryX / X)
L2  dotnet/Core/         one class per Slang object: SlangGlobalSession, SlangSession, SlangModule,
                         SlangEntryPoint, SlangComponentType (unlinked), LinkedProgram,
                         TypeConformance, SlangMetadata, SlangCompileResult, SlangFileSystem;
                         Core/Reflection/: one class per slang::*Reflection type
L1  dotnet/Interop/      SlangObject (owned) and SlangReflectionObject (borrowed), blobs,
                         SlangResult -> exceptions with diagnostics, UTF-8, [UnmanagedCallersOnly]
                         thunks, the version guard, CompanionLibraries, the missing-library hint
L0  dotnet/Native/       ClangSharp output. Only SlangApi.cs holds DllImports
```

```
SharpSlang.Pipeline.Bake  -> SharpSlang, SharpSlang.Pipeline       the cooker
SharpSlang.Pipeline.NRI   -> SharpSlang.Pipeline, SharpNRI.Descs   the projection, stored at bake time
SharpSlang.Pipeline       -> SharpSlang.Descs                      the reader: no compiler
SharpSlang                -> SharpSlang.Descs                      the binding: names no pipeline package
```

- The pipeline packages use only `SharpSlang`'s public API: no `InternalsVisibleTo`, no `SlangApi`,
  no L0 interface struct or reflection handle. `AssemblySplitTests` reads every assembly's
  references and the cooker's type references from metadata.
- **The reflection objects** are one class per `slang::*Reflection` type, one member per
  `spReflection*` function, named after Slang's getter (parameterless ones as properties). They
  borrow: every member checks the owning program, module or entry point and throws
  `ObjectDisposedException` once it is disposed; two wrappers over one pointer are equal. The two
  calls that end the process are left out: `spReflectionType_GetSpecializedElementCount` (U1) and
  `spReflection_specializeType` (U4).
- **No target is chosen for the caller.** Every call that reads one target takes the index,
  required (`GetEntryPointCode*`, `GetTargetCode`, `GetLayout`, `FindType`, the metadata and compile
  results, and in the cooker `Reflect`, `Walk`, `Bake`, ...), so a call reads as the Slang call it
  makes whatever the session holds. A type found by name is the same `TypeReflection` from either
  target's layout.
- **The diagnostics policy stays in L1.** `SlangDiagnostics.Policy` (throw on an error-level
  diagnostic from a successful call) runs inside every call that returns a diagnostic blob; it is
  the guard for Slang reporting degraded output on a successful result (U9).
- `SharpSlang.Descs` references nothing but `System.Runtime` and declares no P/Invoke (0 `ImplMap`,
  0 `ModuleRef` rows); the split is by file in `NativeSplit.props`, so the two projects cannot
  disagree about where a type lives. The interface structs live there because none names the
  library: their methods call through the `lpVtbl` of an object the caller already holds.
- L1: `SlangObject` takes a native reference on its whole ancestor chain and counts its live
  children; failures become `SlangException` with the call name and Slang's text (the diagnostic
  blob, or the thread's `slang_getLastInternalErrorMessage` when a failed call left none); host
  callbacks are `[UnmanagedCallersOnly]` thunks, and no managed exception crosses into Slang.
- L2 does not add locks, dispose children for a parent, or hide Slang behaviour behind defaults
  other than the header's. A parent refuses `Dispose` while a child it made lives; no wrapper has a
  finalizer.
- Escape hatches, in order: the wrappers; each one's `NativeHandle`; the generated vtable structs;
  `SlangApi`'s P/Invokes.

### Upstream shape

Slang's public surface is `include/slang.h` plus `include/slang-deprecated.h`, which it includes.

- **COM-style interfaces.** `SLANG_MCALL` is `__stdcall` on Windows and empty elsewhere, a no-op on
  64-bit, so the generated `delegate* unmanaged[Stdcall]` serves every RID. No vtable method takes
  or returns a struct by value. `SLANG_NO_THROW` is `__declspec(nothrow)` on Windows and empty
  elsewhere, and C++17 makes `noexcept` part of a function type, so a probe has two ABI shapes.
- **Flat C functions.** The reflection API is flat C (`spReflection*`, in `slang-deprecated.h`);
  the C++ reflection classes are inline forwarders with no vtable, so the flat functions are the
  reflection ABI for C++ callers too.

The committed L0 binds 279 flat exports (173 `spReflection*`, 20 `slang_*`, 86 other `sp*`) and
declares 28 interfaces, 231 vtable methods, 374 vtable slots counting inherited ones, and 58 enums;
the 12 C++ reflection veneer types are excluded and declared as empty opaque structs. Two exports
are deliberately not bound, `spReflection_GetSession` and `slang_getEmbeddedCoreModule`, both of
C++ linkage (U11). The ABI oracle checks 51 struct sizes, 116 field offsets, 2 bitfield accessors,
279 free-function signatures and 231 vtable methods. `NativeExportTests` resolves all 279 bound exports
against the loaded library, and `VtableOrderTests` derives all 374 slot indices from the header's
declaration order.

### Unbound surface

Every unbound function has a reason; `VtableOrderTests`, `SurfaceCoverageTests` and the generator's
IID check hold the list, and `tools/coverage/BoundSurface` names every unbound slot, export and
field (`_build/coverage/bound.json`).

- The reflection API is bound whole but for U1's and U4's two calls (Layers).
- The legacy compile-request API (`ICompileRequest`, `createCompileRequest`, the flat `sp*` request
  family) and the language-server surface: unbound by decision. `spReflection_ToJson` takes a
  request and is called with null.
- Record/replay, the bytecode VM, coverage tracing, `ISlangProfiler`,
  `IModulePrecompileService_Experimental`, cooperative-type metadata: no use in a cooker or a
  renderer; generated, not wrapped.
- CPU host code (`getEntryPointHostCallable`, `getTargetHostCallable`): needs `slang-llvm`, not staged.
- `slang_createGlobalSession` (v1) and `...WithoutCoreModule`: `slang_createGlobalSession2` is used.
- Flat aliases of vtable methods (`slang_loadModuleFromSource`, `spSessionCheckPassThroughSupport`,
  `spFindProfile`, ...): second doors. The other way round, `spFindCapability`,
  `spSessionCheckCompileTargetSupport` and `spGetBuildTagString` are bound instead of their slots.
- `IGlobalSession`'s compiler configuration (downstream paths, preludes, the core and builtin
  module cycle, the shared-library loader, `setSPIRVCoreGrammar`, `parseCommandLineArguments`, ...):
  a SPIR-V and DXIL cook configures none of it.
- `ISession`'s type-system queries (`specializeType`, `getTypeLayout`, the RTTI and witness queries,
  `getLoadedModule*`, ...): the reflection objects answer the layout questions, and L2 holds the rest.
- `IComponentType::getSession`, `getResultAsFileSystem`, `renameEntryPoint`; `ISlangClonable::clone`.
- `slang_shutdown`: never called; it tears down process-wide state.
- `slang-rhi`, `gfx`: out of scope; the renderer is NRI through SharpNRI.

### Native packages

| Package | Native content | Notes |
|---|---|---|
| `SharpSlang` | `runtimes/<rid>/native/`: `slang-compiler`, `slang-glslang` (carries `spirv-opt`); `standard-modules/<rid>/slang-standard-module-<version>/`; `licenses/<rid>/` | win-x64, linux-x64, linux-arm64 in a release; osx-arm64 is a zip on the release. Built from `slang/` by `tools/build-native.ps1`. `buildTransitive/SharpSlang.targets` puts the module folder beside the compiler and the notices beside the application |
| `SharpSlang.Descs` | none | `SharpSlang` and `SharpSlang.Pipeline` depend on it exactly; another restored version fails the build (`SHARPSLANG005`) |
| `SharpSlang.Dxc` | none | targets only; exact dependency on `Microsoft.Direct3D.DXC` `[$(DxcPackageVersion)]`; copies `dxcompiler.dll` and `dxil.dll` on win-x64; another version fails the build (`SHARPSLANG011`) |
| `SharpSlang.Pipeline`, `.Bake`, `.NRI` | none | exact dependencies as under Layers; the projection on `SharpNRI.Descs` `[$(SharpNriDescsPackageVersion)]`, no `NRI` library |

- **Standard modules.** An `import` the session's search paths do not resolve is looked for in
  `<directory of the library exporting slang_createGlobalSession>/slang-standard-module-<version>/`,
  the import path's dots as folders (`source/slang/slang-session.cpp`, `getStandardModuleDirPath`);
  the folder name is compiled in. NuGet copies `runtimes/<rid>/native/` flat, which breaks that
  folder (`E00001` "cannot open file 'slang/neural.slang'"), so the package carries it outside
  `runtimes/` and the build targets copy it, folders kept, beside the application for a
  RID-specific build, `publish -r` and Native AOT, and under `runtimes/<rid>/native/` for a portable
  build. Every standard module is `[ExperimentalModule]`: without `SessionOptions.ExperimentalFeatures`
  the import is refused (`E00104`). `StandardModuleTests` holds both codes.
- **Recorded source paths (U36).** Each `.slang-module` records its `.slang` sources relative to the
  folder Slang compiled it in, and Slang resolves that path from the folder the module is loaded
  from; when a file exists there it is named among the dependency files (never read). An output
  five folders below a Slang checkout names the checkout's file, which is why `tools/consume` builds
  in the system temp folder.
- **Licences** are packed as `licenses/<rid>/` (NuGet ignores the rest of `runtimes/<rid>/`) and
  copied to `licenses/SharpSlang/<rid>/` beside the application; `SharpSlangCopyLicenses=false`
  copies none.
- **Debug information.** Every package with an assembly carries its portable PDB and names its
  commit; Source Link is the SDK's own and maps the repository and `slang/` to their commits,
  checked by `check-packages.ps1`. The native symbols (`SLANG_ENABLE_SPLIT_DEBUG_INFO`) go on the
  GitHub release as zips, checked against the library by `tools/ci/native-symbols.ps1`.
- **Trimming and Native AOT** are declared (`IsAotCompatible`) on the five assemblies; the layout's
  JSON is a source-generated `JsonSerializerContext` (`ProgramLayoutJson`), so a cooker published
  with Native AOT warns nothing. `Assembly.Location` (empty in single-file and AOT) is handled where
  read and suppressed with that justification.
- **Descriptions** are typed except `SharpSlang`'s platform list, which a target writes at pack time
  from what is staged, refusing a pack with no payload (`SHARPSLANG001`).
- **What is staged**: `slang-compiler` under its plain name and `slang-glslang` under its versioned
  one (the `DllImport` resolves the first; Slang `dlopen`s the second by its versioned name), the
  standard modules, the licences and third-party notices. Not staged: `slang-llvm`, `gfx`,
  `slang-glsl-module` (only with `-WithGlslModule`), the executables. `-StandardModules
  WithoutNeuralNumerics` stages workgraph and functional only (most of the size is the numerics
  modules); the default, `All`, is the release's set.
- **Versions**: `SharpSlangVersion` is the release (`SharpSlang`, `.Dxc`, `.Pipeline.Bake`,
  `.Pipeline.NRI`); `SharpSlangDescsVersion` and `SharpSlangPipelineVersion` move only when their
  sources change (`tools/ci/descs-version.ps1`). Dependencies between this repository's packages
  are exact.

## Rules

Decided; not reopened as a side effect of other work.

- **Nothing of ours in C or C++.** The binding is managed code over a pinned native build; the
  repository's native content is the patch set.
- **Every Slang defect found is recorded**: in the registry and `docs/upstream.md` as report text,
  filed or not, and here as a caveat when the binding is built around it. Filing is the owner's
  trigger: nothing is posted upstream without the owner reading the exact text (`CLAUDE.local.md`).
- **A Slang defect is patched test first.** The test asserts the right answer and is run red against
  the unpatched build; the patch makes it green. While Slang's release payload is also supported,
  the binding's guard stays and the release's wrong answer is asserted as wrong, so the release that
  fixes it fails a test naming the guard. Never a test shaped around a defect or a "to fix" skip.
- **A patch is Slang-shaped**: Slang's coding conventions, comments in Slang's declarative voice, a
  regression test under Slang's own test tree, never a semantic change to an existing call, never a
  reordered, inserted or removed vtable method or enumerator.
- **Third-party defects are worked around and recorded, not patched**: drivers, lavapipe, the Khronos
  layers, dxc, NRI, the .NET runtime.
- **The library knows nothing about any consumer.** No project, test, package or document names an
  engine or product of ours.
- **No vendor runtime shipped whose licence a library cannot meet.** dxc reaches applications
  through `SharpSlang.Dxc`, which depends on Microsoft's package and copies from it.
- **Claims are measurements.** Ownership, refcount and platform claims are measured and pinned by a
  test, never derived from COM convention, documentation or one platform.
- **Oracles outside the binding** for every claim (Tests and skips). The binding's description of
  itself is not an oracle, and Slang describing itself is a weak one.
- **No meaningless tests.** A skip names the missing capability (a library, a compiler, a device
  feature, a file); a platform skip quotes a measured defect or an owner decision. A question whose
  answer may end the process runs in the prober.
- **No stale figures.** A figure names how it was measured; tooling discovers the machine at run time.
- **No finalizers.** A forgotten `Dispose` leaks; it never corrupts.
- **Zero allocation per frame applies to `SharpSlang.Pipeline`**: every lookup a renderer makes after
  load allocates nothing, measured. The compiler binding is exempt: it runs at cook time.
- **Don't flood CI** (Actions budget). Verify locally on every platform the machine has (Windows,
  WSL) first; one run per head, only when it is expected to pass.
- **Code cites these notes by heading anchor**, `AGENTS.md#<anchor>`. `tools/ci/check-docs.sh` fails
  on an anchor with no heading, so renaming a heading updates its citations in the same change.
- `slang/` and `patches/` are not changed as a side effect of other work. Stage by path.

## Build and test

### Windows

```powershell
pwsh tools/build-native.ps1 -Rid win-x64     # Slang from slang/ with patches/ (Native build); or
pwsh tools/fetch-native.ps1 -Rid win-x64     # Slang's own release archive, unpatched
pwsh tools/check.ps1                         # lint and zero-alloc
dotnet build SharpSlang.slnx -c Release -warnaserror
dotnet test  SharpSlang.slnx -c Release
dotnet run --project samples/SharpSlang.Smoke -c Release
```

`runtimes/` is git-ignored, so a fresh clone stages a payload first; after changing `<SlangVersion>`
stage again, or the version guard refuses the old one. After swapping payloads, build with
`--no-incremental`: an incremental build keeps the previous copy in the output directories, and
`The_library_under_test_is_the_one_staged` fails naming it.

`fetch-native.ps1`: `-Rid` (default the host; cross-RID staging works), `-Profile` (`Minimal`,
`Spirv` the default, `Glsl`), `-SlangVersion`, `-Force`; the archive is cached in `obj/slang-dist/`.

Tools found at run time, each a skip naming it when missing: a C++ compiler (clang++ or LLVM;
`NativeAbiTests`), `spirv-val` and `glslangValidator` (the Vulkan SDK, or `apt install spirv-tools
glslang-tools`), naga (`cargo install naga-cli --locked`), a CUDA toolkit for NVRTC, Xcode for
`metal`. dxc comes with the test project.

### Linux (WSL2 Ubuntu 24.04)

```bash
pwsh tools/build-native.ps1 -Rid linux-x64 -AllowNewerGlibc   # or fetch-native.ps1 -Rid linux-x64
bash tools/ci/verify-linux.sh                                  # build, full suite, spike, CI's allocator settings
```

Run it from a Linux-filesystem clone: a worktree shared between Windows and WSL picks up Windows
binaries. The NRI device tests on Vulkan need the Khronos layer 1.4.363 or newer in front of
Ubuntu's (CI runners and flakes). From a Windows shell into WSL, write a script file, strip CR, run
it with `bash -l` or put `~/.dotnet` and `~/.dotnet/tools` on its `PATH`.

### macOS

Verified on the CI `osx-arm64` leg (`macos-15`), on demand and weekly. No Vulkan loader: the Vulkan
tests skip with their reason, and the NRI device tests do not run on macOS by decision.

### Native build

```powershell
git submodule update --init --recursive slang      # Slang at the pinned tag, with external/
pwsh tools/build-native.ps1 -Rid win-x64           # or linux-x64 / linux-arm64 / osx-arm64, on that OS
```

It checks `slang/` against `<SlangVersion>` and its nested submodules, applies `patches/`,
configures with Ninja into `_build/<rid>/`, checks each library's imports, RUNPATH or LC_RPATHs and
(Linux) glibc floor, stages `runtimes/<rid>/` through an allowlist with a `payload.json`, and prints
what it staged. Without a staged library the binding's build stops with `SHARPSLANG001`;
`-p:SharpSlangRequireNative=false` skips that.

| Flag | Meaning |
|---|---|
| `-Rid` | `win-x64`, `linux-x64`, `linux-arm64`, `osx-arm64`; the host's only, no cross-compiling |
| `-StandardModules` | `All` (default) or `WithoutNeuralNumerics`; staging only |
| `-WithGlslModule` | also stage `slang-glsl-module` |
| `-AllowNewerGlibc` | Linux: stage a build above the pinned glibc floor, for local test builds (Pin and payload) |
| `-WithoutPatches` | reverse any applied patch, apply none, build into `_build/<rid>-unpatched/`: the payload a patch's test runs red against; never one to pack |
| `-WithSlangTests` | build Slang's test tools too (tests, slang-rhi, slangc, slangd) into `_build/<rid>-tests/` with the patches, and run each patch's `SLANG_UNIT_TEST` with `slang-test`; stages nothing |
| `-Configuration` | `Release` by default |
| `-Clean` | delete `_build/<rid>/`, downloads included, first |

Toolchains: Windows needs Visual Studio with the C++ x64 tools (the script enters its developer
shell and uses its Ninja) and Python 3; Linux needs GCC, CMake 3.22+, Ninja and Python 3, and a
release builds on Ubuntu 22.04 for the glibc floor; macOS needs Xcode and Ninja. Every RID has built
and been tested on the GitHub-hosted runners (the manual run's `from_source` input; Actions budget).

after the configure the script fails on any `SLANG_*` cache entry it neither passed nor lists as

| `SLANG_ENABLE_RELEASE_DEBUG_INFO`, `SLANG_ENABLE_SPLIT_DEBUG_INFO` | ON | symbols beside the libraries, for the symbol zips |

| `SLANG_USE_SCCACHE` | OFF | and `$env:SLANG_USE_SCCACHE` is cleared: Slang reads it from the environment |
| `SLANG_USE_SYSTEM_*`, `SLANG_OVERRIDE_*_PATH`, `SLANG_SPIRV_HEADERS_INCLUDE_DIR`, `SLANG_ENABLE_EXTERNAL_COMPILER_WARNINGS` | OFF | every dependency from `slang/external/` |
| `SLANG_VERSION_FULL`, `SLANG_VERSION_NUMERIC` | the pin | Slang reads its version from `git describe`, which gives 0.0.0 without tags and renames the libraries |
| `CMAKE_MSVC_RUNTIME_LIBRARY` (Windows) | `MultiThreaded` | the static C runtime |
| `CMAKE_BUILD_WITH_INSTALL_RPATH` (not Windows) | ON | the release's RPATH (Pin and payload) |

The only configure-time download is DXC (`slang/cmake/FetchDXC.cmake`, SHA-256 pinned there), not
staged. The offline key in `_build/<rid>/_deps/.sharpslang-deps` is the Slang commit, the nested
submodule commits, the patch set, the options, the compiler and the DXC pin: while it matches the
configure runs disconnected; when it moves, the tree is deleted, downloads included.

### Regenerating L0

```powershell
dotnet tool install --global ClangSharpPInvokeGenerator --version 21.1.8.4
pwsh tools/generate-native.ps1
```

The script fetches the headers at the pin into `obj/slang-headers/<version>/`, generates,
post-processes (Generator and ABI), carries the header comments in as XML docs and prints the
counts. Review the diff: a reordered `[VtblIndex]` is a silent ABI break, which `VtableOrderTests`
and `NativeAbiTests` see. `regen.yml` regenerates and fails on any diff. Output is LF
(`.gitattributes`). ClangSharp is pinned because its output is the compared input (a newer version
writes `slang::IBlob **` where this one writes `IBlob **`).

### Lint

## Patches

`docs/upstream.json` is the registry, one entry per defect, and the single source of truth;
`docs/upstream.md`'s index is generated from it (`pwsh tools/ci/patch-registry.ps1 -Write`). Every
moderate or large Slang defect gets a patch, test first; the rest are known issues (owner). The
format of a patch is in `patches/README.md`.

- **Fields**: `id`, `title`, `area`, `kind` (`Slang defect`, `Slang documentation defect`, `not a
  defect`), `patch` (the file, or null), `test` (`Class.Method`), `state`, `verified` (the Slang
  version last measured against), optional `upstream` (a Slang issue or PR for the same defect).
  States: `patched`, `fixed upstream in vYYYY.RR`, `filed: <URL>`, `upstream PR from fork: <URL>`,
  `not patchable: <reason>`, `known issue: <reason>`, `unpatched`.
- **The checker**, `tools/ci/patch-registry.ps1`, runs in lint and (registry half) in
  `check-docs.sh`. It fails on a patch with no entry, an entry naming a missing patch, a carried
  entry with no test or one not in `tests/`, a patch with no prose header, a stale index, and a
  patch that does not apply to the pinned tag in order, alone, or under the `-C0` reverse check. It
  reads the base files from `slang/`'s object store or raw.githubusercontent.com, so lint needs no
  submodule. It cannot see a hunk whose line count truncates the file it adds; `-WithSlangTests`
  compiles those files.
- **Which payload a test runs against** is read from `runtimes/<rid>/payload.json` (`source:
  release` from `fetch-native.ps1`, `source: build` with each applied patch and its SHA-256 from
  `build-native.ps1`). `[PatchedFact("Un")]` asserts the right answer and skips on the release;
  `[ReleasePayloadFact("Un")]` asserts the release's wrong answer and skips on a source build. A
  test whose defect is one platform's skips elsewhere, naming it.
- **CI tests Slang's release payload** until the repository variable `SHARPSLANG_NATIVE_FROM_SOURCE`
  is `true` (Decisions); a manual run's `from_source` input does the same for one run. Then
  `native-from-source` builds each RID (Linux on Ubuntu 22.04 for the glibc floor), the legs restore
  that payload only, and a gate fails a leg on a carried entry's test failing or skipping for want
  of the patched payload.
- **Verifying a patch batch**: on Windows and under WSL, each entry's test red against
  `build-native.ps1 -WithoutPatches` and green against the patched build; Slang's own regression
  tests with `-WithSlangTests`; the full suite on the patched build and on the release payload.
- **A Slang bump**: check out the new tag in `slang/`, then `pwsh tools/ci/patch-registry.ps1 -Bump`
  on Windows and under WSL. It reports whether each patch applies to the new tag, builds the tag
  without the patches, and runs each carried entry's test: red keeps the patch, green means the tag
  carries the fix (drop the patch, state `fixed upstream in <tag>`); a theory counts every row.
  Then re-cut what no longer applies, restage the patched payload, run the full suite, move every
  `verified`, and `-Write`.
- **Applying and cutting**: `build-native.ps1` applies `patches/*.patch` in name order and skips one
  already applied (reverse check with `-C0`). A patch is a `git diff` against the tag with a prose
  header, cut in a scratch clone with the earlier patches committed when it touches the same file;
  every patch applies in order and alone. Each carries Slang's regression test under
  `tools/slang-unit-test/` where its behaviour does not depend on how the process is launched.

## Decisions

The owner's, unless said otherwise.

- **CI tests the patched build**: the repository is public and `SHARPSLANG_NATIVE_FROM_SOURCE` is
  set, so every leg restores the payload built from source with `patches/`. A release packs payloads
  built from source with the patches, whatever the variable says.
- **Name: SharpSlang. Packages: `SharpSlang`, `.Descs`, `.Dxc`, `.Pipeline`, `.Pipeline.Bake`,
  `.Pipeline.NRI`.** The pipeline packages fill the template's `<Binding>.<Feature>` slot and use
  only the binding's public API; the reader is separate from the cooker so an application that
  ships baked packages carries no compiler, and the NRI projection is separate so the reader does not
  pull NRI's descs.
- **The binding knows nothing of the pipeline** (no `InternalsVisibleTo`).
- **No Vulkan projection**: the pipeline projects onto NRI only, at bake time
  (`SharpSlang.Pipeline.NRI` runs in the cooker); the raw-Vulkan validation oracle runs on SharpNRI's
  validated Vulkan device.
- **Versions**: the major is the Slang version as a fixed-width YYYYRRP (v2026.21 is `2026210.B.F`),
  so every Slang release is a new major, which it is; within one Slang version a breaking change
  moves B and a fix moves F. Assembly and file versions are `YYYY.RRP.B.F` (16 bits a part).
- **Each compile target is held to its strongest outside oracle**: a device where one runs here
  (SPIR-V on Vulkan, DXIL on D3D12, through SharpNRI), a validator otherwise, compile-only and named
  as such where neither exists.
- **Unbound by decision**: the legacy compile-request API and the language server.
- **Zero allocation per frame** for `SharpSlang.Pipeline`, not the binding.
- **No `SharpSlang.Testing`**: SharpNRI.Testing provides the devices the pipeline tests use.
- **Default branch `master`, public, with its full history.** Rulesets: `master` takes changes
  through a pull request with the "ci" status green and up to date, and is never force-pushed or
  deleted; `v*` tags are never moved or deleted. Secret scanning, push protection and Dependabot
  alerts are on; outside contributors' workflow runs need approval. Packages go to nuget.org by
  Trusted Publishing, through the `nuget` environment the owner approves (The release).
- **CI is manual on branches, `master` reruns only untested trees, a "ci" commit status gates
  merges, macOS on demand and weekly; nothing in a release waits for macOS.**
- **Upstream filing is the owner's trigger** (`CLAUDE.local.md`).
- **Pure managed P/Invoke; L0 generated by ClangSharp in C++ mode, everything above hand-written**:
  L0 is the only layer that churns on a Slang bump, and generating it makes a bump a reviewable diff.
- **dxc by dependency, not redistribution**: Microsoft's licence forbids a stand-alone offering of
  the files, so `SharpSlang.Dxc` carries none and the consumer restores Microsoft's package.
- **Reflection is projected to an immutable managed snapshot, walked once, never proxied**: Slang's
  reflection pointers belong to the component type that produced them, so a proxy is a
  use-after-free; a snapshot outlives it and serializes.
- **No finalizers; every wrapper holds its whole ancestor chain** (Ownership and lifetime).
- **Standard modules in `standard-modules/<rid>/`, copied beside the compiler by build targets**;
  `SessionOptions.ExperimentalFeatures` (off by default, as in Slang) imports them.
- **Notices beside the application** (`licenses/SharpSlang/<rid>/`), opt-out `SharpSlangCopyLicenses=false`.
- **Trimming and Native AOT declared on every shipped assembly.**
- **SharpNRI from nuget.org at exact versions** (`SharpNriPackageVersion` for the tests,
  `SharpNriDescsPackageVersion` for the projection, the same Descs SharpNRI depends on).
  `SharpNRI.AgilitySDK` is not used: in Release it disables D3D12 validation, which the tests need.
- **Pins are exact.** A Slang bump is a breaking change; a `SharpNRI.Descs` bump can move a field.
- **Linux test runners on Ubuntu 24.04**: the lavapipe steps install by package name.
- **The default diagnostics policy throws on an error-level diagnostic from a successful call**;
  `RequireSpirvOptimizer` and `RequirePinnedSlangVersion` default on.

## Oddities and caveats

Each: the fact, how it is handled, and the caller's rule. "Un" names the defect in `docs/upstream.md`;
whether the packaged compiler carries a fix is in the registry. Where a binding guard exists for a
defect, it stays while Slang's release payload is supported.

### Generator and ABI

- **ClangSharp's residue is fixed in `tools/generate-native.ps1` only**, each workaround against a
  failure: the redundant `using System;` removed; no `[assembly: GeneratedCode]`; the COM-name twins
  (`QueryInterface`, `AddRef`, `Release` beside Slang's slots) removed; a message on the two
  `[Obsolete]`; `struct Attribute` remapped to `SlangAttribute`; the 12 C++ reflection veneer types
  excluded and declared opaque (C++ `this` is a pointer); `getTypeGuid` excluded and the IIDs parsed
  out of `slang.h` (`ICompileRequest` has none); the callback typedefs ClangSharp writes as
  `unmanaged[Thiscall]` rewritten to `Cdecl` (a silent ABI mismatch otherwise); three inline helpers
  doing pointer arithmetic on `this` rewritten with `Unsafe.AsPointer`; the `SpecializationArg.Kind`
  `using static` dropped; `createGlobalSession` excluded (L1 writes it); the two C++-linkage
  functions excluded (ClangSharp binds them by MSVC mangling, U11).
- **C++ mode, and no enum is erased.** `slang.h` does not parse as C. In C++ mode every enum-typed
  parameter, field and return is that enum, and the script fails a regeneration where an enum name
  sits on an integer. The integer flag types are integer typedefs with values in anonymous enums.
- **Header comments become XML docs** (`generate-native-docs.ps1`); `<param>` only when the names
  match the generated parameters.
- **ClangSharp mechanics**: it exits non-zero on macro warnings after generating, so the script
  checks the file count; only `slang.h` is passed as `--file` (the other header in `--traverse`);
  every signature is blittable, so `DllImport` costs no marshalling.
- **Compiling is not correctness: the ABI oracle.** A wrong offset, size, bitfield packing or
  parameter list compiles and dispatches. `NativeAbiTests` generates a C++ probe from the C#
  metadata and compiles it against the pinned `slang.h` as `static_assert`s.
- **Slot order cannot be probed** (Slang's interfaces have no key function), so `VtableOrderTests`
  derives every slot index from declaration order; for the slots the binding never calls, it is the
  only check.
- **Both oracles read `dotnet/Native/*.cs` as text**: `VtblIndexAttribute` and
  `NativeTypeNameAttribute` are `[Conditional("DEBUG")]`, absent from Release builds.
- **Two ABI shapes**: compile the probe with and without `-DSLANG_NO_THROW=` before calling a probe
  change verified.

### Descriptor defaults and result codes

- **ClangSharp drops C++ default member initializers.** Zero-initialised descs compile and
  mis-compile: `SessionDesc.defaultMatrixLayoutMode` is `ROW_MAJOR` in C++ and 0 zeroed,
  `TargetDesc.flags` loses `GENERATE_SPIRV_DIRECTLY`, `structureSize` is 0. Handled:
  `dotnet/Defaults.cs` factories; `DefaultsDriftTests` re-reads the header. Caller's rule: start
  from `Defaults.Create*()`, never `new`.
- **Result codes are function-like macros**, which libclang does not evaluate; `dotnet/SlangResult.cs`
  transcribes them and `SlangResultDriftTests` re-reads the header.

### Pin and payload

- **The payload must be the pinned release.** `SlangGlobalSession.Create` compares
  `spGetBuildTagString` with the pin and throws `SlangVersionMismatchException` naming both and the
  loaded library's path (from the module list, or `dladdr` on Unix). A payload with a reordered
  interface calls the wrong function, so this is not defensive. `RequirePinnedSlangVersion = false`
  opts out.
- **The loaded Descs must be the ones SharpSlang was built with**, checked first in `Create`: its
  Slang version and package version against SharpSlang's metadata; not covered by the opt-out. A
  direct reference to another Descs version restores with only NU1608, so the packed targets fail
  that build (`SHARPSLANG005`). `VersionGuardTests`.
- **Versions, twice**: `Slang.SlangVersion` and `SlangHeaders.Version` are compiled in;
  `Slang.BindingVersion`, `BindingSlangVersion`, `DescsVersion`, `DescsSlangVersion` read the loaded
  assemblies.
- **A major of 2026210 does not fit an assembly version** (16 bits a part; CS7034), so
  `Directory.Build.targets` splits it: package `2026210.B.F` is assembly `2026.210.B.F`; the guard
  reads the informational version. `SHARPSLANG004` fails a packable project whose version does not
  encode `SlangVersion`.
- **A missing `slang-compiler` is explained** (`Interop/NativeLibraryHint.cs`): the first calls into
  Slang catch `DllNotFoundException` and throw one naming the file, the RID, the directories looked
  in and where the library comes from. Its `ResolvingUnmanagedDll` handler only records the miss:
  it never returns a handle or throws, because the event stops at the first handler that does, and
  there is no DllImport resolver (that is the application's).
- **The payload says where it came from**: `runtimes/<rid>/payload.json` (Patches).
  `NativePayloadTests` requires it, the compiler's hash to match the staged file and its copies, and
  a build's patch list to be exactly `patches/`.
- **The library is `slang-compiler`** (renamed upstream from `slang`, which collides with S-Lang on Linux).
- **Release archive layout**: Windows keeps libraries in `bin/`, Unix in `lib/` with versioned names;
  `Expand-Archive` writes symlinks as text stubs, so staging matches by glob and takes the largest file.
- **Licence files are staged beside `native/`, as `LICENSE.txt`**: NuGet treats an extensionless
  `PackagePath`, or one whose extension differs from the source's, as a directory.
- **The Linux payload has a glibc floor, set by the build host.** Slang's release needs at most
  GLIBC_2.34 and GLIBCXX_3.4.29; a build on Ubuntu 24.04 needs 2.38 and 3.4.32 and would not load on
  22.04. Handled: the floor is pinned in `Directory.Build.props`; `build-native.ps1` refuses a build
  above it unless `-AllowNewerGlibc`; `NativePayloadTests` fails on one unless
  `SHARPSLANG_ALLOW_NEWER_GLIBC=1`; CI and the release build Linux on Ubuntu 22.04.
- **A library staged from Slang's build tree searched the working directory**: CMake's build-tree
  RUNPATH ends in an empty entry. Handled: `CMAKE_BUILD_WITH_INSTALL_RPATH=ON`; the script and
  `NativePayloadTests` require `$ORIGIN/../lib:$ORIGIN` (macOS: `@loader_path/../lib`, `@loader_path`).
- **Slang's release libraries for osx-arm64 declare macOS 26 as their minimum**; the source build
  sets 15.0 and checks it.
- **Slang's licences ask for third-party notices**, which both staging scripts stage as
  `third-party-notices/<name>.txt`.
- **Slang's version comes from `git describe`**; `build-native.ps1` passes it from the pin.

### Companion libraries and dxc

- **`slang-glslang` is required in practice.** Without it Slang emits unoptimised SPIR-V on a
  successful result and reports the missing optimiser (U9). Handled:
  `GlobalSessionOptions.RequireSpirvOptimizer` (default on) asks `checkPassThroughSupport` at session
  creation; the default diagnostics policy throws on an error-level diagnostic.
- **Windows does not search the compiler's own directory for its companions** (U10): Slang loads
  `slang-glslang`, `slang-glsl-module` and `dxcompiler` by bare name through
  `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`, which does not include the directory of
  `slang-compiler.dll`. Handled: `CompanionLibraries.Preload`, Windows only, once per process,
  loads them from the compiler's directory (dxc also from `AppContext.BaseDirectory`) by full path
  and never frees them (Slang frees its own when a global session goes).
  `ProberTests` launches the prober as `dotnet <dll>` from an empty directory on every leg.
- **Linux and macOS find them by rpath** (`$ORIGIN`, `@loader_path`).
- **Slang ships no dxc.** `SharpSlang.Dxc` copies `dxcompiler.dll` and `dxil.dll` from
  `Microsoft.Direct3D.DXC`; `CreateSession` refuses a DXIL target without loadable dxc, naming the
  package. The pinned dxc signs with its internal validator and never loads `dxil.dll`, which is
  still copied for a dxc that does.
- **The dxc targets** read the restored `Microsoft.Direct3D.DXC` version from `project.assets.json`
  and fail another (`SHARPSLANG011`; none restored `SHARPSLANG010`; the pin without its DLLs
  `SHARPSLANG012`) before `BeforeBuild`, on every host; they copy on win-x64 only.
- **`buildTransitive/` does not flow through a `ProjectReference`**, so a source consumer references
  `Microsoft.Direct3D.DXC` at `DxcPackageVersion` and imports the targets itself, as the tests do.

### Ownership and lifetime

- **`ISession::loadModule*` returns a borrowed pointer** (U12): the session retains its modules, and
  releasing the returned pointer over-releases (glibc aborts; Windows tolerated it). Handled:
  `SlangModule` takes its own reference on adoption.
- **A child does not retain its session**: `ISession` retains `IGlobalSession`, but a module or a
  linked program does not retain its session.
- **Slang destroys the global session inside `~Linkage` when the Linkage holds the last reference**
  (U13), a double free seen on macOS. Handled: every wrapper holds a native reference on its whole
  ancestor chain, released nearest first, and asserts it as a number
  (`The_global_session_is_never_destroyed_from_inside_the_linkage`).
- **No finalizers.** Double dispose is a no-op; use after dispose throws `ObjectDisposedException`.
- **A parent refuses `Dispose` while a child it made lives** (`SlangObject.LiveChildren`): a forgotten
  child leaks both, never corrupts. Caller's rule: dispose children first; `using` in creation
  order does it.
- **Borrowed reflection objects check their owner on every read.**
- **A host filesystem must outlive the session**: `SlangFileSystem.Dispose` refuses while a session
  created with it lives. Returning null from a provider is a miss; a throw becomes a failure code.
  `CallbackBoundaryTests` drives every slot with null and throwing inputs.

### Reflection snapshot

- **An unlinked composite reflects** the same parameters, bindings and entry points as the program
  linked from it (`CompositeTests`); `createCompositeComponentType` retains each component, and the
  wrapper takes its own reference too.
- **Reflection pointers are interior pointers** owned by the component type that produced them. The
  walk reads them through the borrowed reflection objects and nothing native leaves it; the
  snapshot outlives program and sessions.
- **The flat functions are the only way in**; the C++ classes' small composites (`isArray()`,
  `unwrapArray()`, ...) are done by the walk itself.
- **A declaration cast back is not the same pointer**, so a round trip is compared by what it reports.
- **The bindless space is reserved whether or not the code uses it**; `ProgramLayout.BindlessSpaceIndex`
  is the reservation.
- **Type names are Slang's canonical spelling** (`float3` is `vector<float,3>`).
- **Overloads are visible only by name**: `FindFunction` gives one function with `IsOverloaded` set
  and an empty signature. Caller's rule: check `IsOverloaded` before `Parameters`.
- **Specializing a generic** (U15): `spReflection_specializeType` on a type from `FindTypeByName`
  returns null; the working route is the type's generic container through `specializeGeneric`, then
  `GetInnerDecl`, `getTypeFromDecl`, `applySpecializations`, applied per parameter variable and to
  the result type. `getSpecializedTypeArgCount` is 0, so arguments are read from `GetFullName`.
- **`specializeGeneric` with a mismatched argument list ends the process** on Windows and Linux (U3).
  Handled: `SpecializeGeneric` compares argument kinds and count first. Residue: a generic mixing
  type and value parameters reports them as two lists, so a wrong order with matching counts reaches Slang.
- **`specializeType` on a non-generic type** returns null on Windows and macOS and crashes on Linux
  (U4; undefined behaviour from an assert that removes its own check). Handled: never called in
  process; `SpecializeGeneric` refuses a non-generic type.
- **Sub-object ranges carry less than their names suggest**: `getSubObjectRangeOffset` returns a
  variable layout with no variable; the space offset of a top-level parameter block is wrong (U33);
  `getBindingRangeDescriptorSetIndex` indexes the enclosing scope's own list. `SubObjectRange`
  carries no space: join on the name against `DescriptorSets`. A plain `ConstantBuffer<T>` is
  reported beside parameter blocks, so it is no `ParameterBlock` detector (U15).
- **Append and consume buffers cost two descriptors**: a counter buffer named `counter`, absent from
  `Parameters`; with both kinds in one shader the counters share the name. Handled:
  `DescriptorRange.CounterBinding`. Caller's rule: build layouts from `DescriptorSets`.
- **Loose global uniforms** become an undeclared constant buffer; Slang reports its binding as 0
  whether or not it exists, so `IsImplicitGlobalBuffer` is gated on its size (U15).
- **User attributes**: asked only of structs; argument values probed by accessor type.
- **Alternate routes agree**: `SecondOpinionTests` requires Slang's second door to each fact to agree.
- **Reflection JSON**: `SlangWalkerCorpusTests` compares the walker with `spReflection_ToJson` and
  Slang's expected results, every JSON key accounted for.

### Sizes Slang does not know

- **"Unknown" is a number**: `SLANG_UNKNOWN_SIZE`, one below `SLANG_UNBOUNDED_SIZE`, returned for an
  array sized by a specialization constant (and the field after it). Handled: `CategorySize.IsKnown`,
  `FieldLayout.IsUniformOffsetKnown`, `ArrayLayout.IsSpecializationSized`. Caller's rule: check
  before arithmetic.
- **Asking such an array for its element count ends the caller** (U1), though the header documents
  `SLANG_UNKNOWN_SIZE`. Handled: the walk reads the size marker and never asks.
- **A resource array sized by a specialization constant cannot be reflected** (U2):
  `getBindingRangeCount` throws through `extern "C"`, catchable on Windows, fatal on Linux and
  macOS. Not guardable. Handled where the compiler reports the count as unknown: the walk refuses it
  by name with `NotSupportedException`. Caller's rule: do not write one (it cannot work on Vulkan,
  where the descriptor count is fixed first).
- **A buffer whose block holds only such arrays gets no binding** (U5). Handled: the projection
  requires a binding for every top-level parameter and refuses by name.
- **An unbounded array reports `0xFFFFFFFF`**: normalised to 0 with `IsUnbounded`. Caller's rule:
  choose the cap.
- **A specialized workgroup dimension reports 0**. Handled: `ThreadGroupSize.IsSpecialized`;
  `GroupCountFor` refuses.
- `getBindingRangeImageFormat` on a non-texture range returns `unknown` (it once crashed); the
  walker's guard stays.

### Layout and the emitted module

- **Matrices are not their components packed**: `float3x3` is 48 bytes; arrays in a constant
  buffer stride 16. `MatrixLayout.Stride`, `ComponentOffset`.
- **`MatrixLayout.Mode` vs the decoration**: row-major in Slang's terms is decorated `ColMajor` in
  SPIR-V. Read `Mode` and `Stride`.
- **Uniform offsets are per target** (std140 against D3D packing); one compute case is declared to
  differ (`SlangComputeCorpusTests.ExpectedToDiffer`).
- **A 64-bit 3- or 4-component vertex input is given one location** where Vulkan requires two (U6).
  Handled: NRI has no 64-bit vertex format, so the projection refuses a `double` attribute.
- **`pName` is `main`**; `BakedEntryPoint.ModuleEntryPointName` is read from the module.
- **The SPIR-V version defaults to 1.5**; pin `SpirvVersion`. `TargetOptions.VerifyEmittedSpirv`
  (default on) reads the emitted header and throws on a mismatch.
- **A specialization-constant workgroup size is emitted as `LocalSizeId`**, which needs `maintenance4`.
- **`ParameterBlocksUseRegisterSpaces` is inert on SPIR-V.**
- **The `sample` modifier needs `sampleRateShading` on the device.**

### Compilation, linking and diagnostics

- **A function without `[shader(...)]` is invisible to `FindEntryPoint(name)`**; the overload taking
  a `SlangStage` reaches it.
- **Link-time options**: `linkWithOptions` accepts every option and ignores many (U16). Handled:
  `LinkTimeOptions` types the ones that take effect (`Optimization`, `FloatingPointMode`); the rest
  go through `RawEntries`, and a raw entry and its typed form emit the same bytes.
- **`GetEntryPointIdentityHash` follows options, not code**: hash `GetEntryPointCodeBytes` for "same code".
- **`isBinaryModuleUpToDate` answers from the session's file cache** (U14). Caller's rule with
  Slang's release: ask from a session that has not loaded the module. A module blob loads only into
  the build that wrote it (`ReadModuleInfo`).
- **Severity is parsed from message prefixes**: `SlangDiagnostics.Classify` does it once.
- **Type conformances**: an implementation reached only through dynamic dispatch needs
  `CreateTypeConformance`; registering a type that does not implement the interface throws.
- **Link is three calls**: `CreateCompositeComponentType`, `SlangComponentType.Specialize`, `.Link` /
  `.LinkWithOptions`, each with its own operation name; `SlangSession.Link` composes them. A wrong
  number of specialization arguments is `E38025`.
- **A composite linked twice emits its first link's code** (U30). `SlangSession.Link` composes afresh
  per call. Caller's rule with Slang's release: one composite per link.
- **A second module from source at a path the session already holds** ends in an internal assert
  (U31). Caller's rule: one path per module from source.
- **Specialization constants**: `Pack` refuses a value of the wrong type by name; a ternary over
  `DefaultFloat` and `DefaultInt` unifies to `double` and hands `Pack` the wrong type.

### DXIL

- **No default profile**: name the shader model in `TargetOptions.Profile`, or Slang picks (6.0 for
  an unprofiled compute shader). The tests name `sm_6_5`. Registers are per class (`b0`, `t0`, `s0`,
  `u0` are four bindings); NRI's D3D12 backend sorts by descriptor type, so one projection serves both.
- `[[vk::binding]]` is ignored on DXIL; `[vk::push_constant]` is dropped, and reflection keeps no
  trace of it (U15). Handled: `NriProjectionOptions.RootConstantParameters` names the blocks.
- Specialization constants become members of an undeclared constant buffer at `b0`; one in
  `numthreads` fails with `E55205`.
- dxc refuses `SubpassInput` and a `double` in a stage signature (`DxilTests.CannotCompile`).
- A DXIL package carries no `SpirvVersion` and no `WorkgroupSize`.
- D3D12 links stages by register in declaration order: the harness puts `SV_Position` last.
- **NRI's viewport origin is top-left on both backends**, so `PixelTests` has one CPU reference.

### The other targets

`TargetValidationTests` judges every target's output with that target's own tool (Tests and
skips); refusals and rejections are declared per entry point, each with its reason, and checked
both ways.

- **GLSL is Vulkan GLSL**, judged by glslang for Vulkan. Tessellation (U18, U19, U34, U35).
- **HLSL** carries Vulkan-only constructs through, which dxc refuses as on DXIL; dxc is run with
  `-E` set to each entry point's Slang name.
- **WGSL**: Slang diagnoses most of what WGSL lacks but not all (U20, U21, U22, U23, U25). naga's
  own gaps (the `immediate_address_space` extension, `subgroups`) are not called Slang defects.
- **Metal**: U23, U26-U29; `rw-texture-simple` exceeds Metal's limit of 8 read_write textures.
- **CUDA** source needs `SLANG_CUDA_ENABLE_HALF` and an architecture NVRTC's default is older than
  (`compute_75`); ray-tracing stages need the OptiX SDK. U23.
- **C++** compiles against Slang's prelude (`prelude/` at the tag; `include/` in the release). U23,
  U24, U32; barriers and atomics are diagnosed (`E36107`).

### Threads

- **A global session and everything made from it belong to one thread at a time**; sharing one
  without a lock can be silently wrong (measured outcomes range from a crash to different SPIR-V on
  a successful result). No outcome holds every run, so none is pinned. Caller's rule: one global
  session per thread, or a lock around every use.
- **One global session per worker** is the pattern; each output equals a serial compile.
- **Back end in parallel after a serialized front end** is supported (experimental in `slang.h`).
- **`SlangDiagnostics.Policy` and `Handler` are process-global.** Set once at startup.

### Pipeline: baking, packages, allocation

- **A baked layout is byte-stable across platforms**: `ProgramLayout.ToJson` writes `\n` everywhere.
- **`Bake(program, module)` hashes the shader and everything it imports or includes**, by content;
  the string overload hashes one file.
- `ShaderPackage.ReadFrom` has one failure mode, `InvalidDataException`; `Bake` reads its own output
  back. `MalformedInputTests`.
- **Format 5 carries optional named sections**, kept whole by a reader that does not understand
  them; older formats are refused with "Rebake".
- **After load, every lookup on the reader and the NRI projection allocates 0 bytes**
  (`AllocationTests`), and a compute frame driven through the projection allocates 0 bytes on the
  managed and the NRI side. Caller's rule: span overloads and indexed loops per frame (a `foreach`
  over `DescriptorSets` boxes).
- **Zero allocation per frame is default-deny**: every public member of the reader and the
  projection counts as per-frame unless it creates an object (`Creates`) or is named in
  `NotPerFrame` with its reason; `AllocationCoverageTests` reads the IL of the measured loops and
  fails naming each member none of them calls, and each listed name that no longer exists.
- **The binding has no per-frame API**: every `SharpSlang` call compiles, links, reflects or hands out
  code once per shader variant.

### NRI projection

- **Projected at bake time**: `package.WithNriProjection(options)` stores the projection as a section,
  read back and compared before it is returned; `ReadNriProjection()` rebuilds the same records at
  load. It records `NriHeaders.Version` and refuses another ("Rebake"). `NriPackageTests` compares
  it field by field with a fresh `ToNri` on every corpus shader, SPIR-V and DXIL.
- Rules read from NRI's Vulkan backend (`PipelineLayoutVK.hpp`); `NriProjectionTests` pins the NRI
  version. On an NRI major bump, re-read them.
- **`SetIndex` is not the register space**: NRI indexes sets by position; its Vulkan backend places
  each at its register space and fills gaps.
- **An unbounded array needs a cap** (`UnboundedArrayCap`); `VARIABLE_SIZED_ARRAY` is legal only on a
  set's last binding, which Slang does not arrange.
- **`ARRAY` on every array range is load-bearing** for NRI's Vulkan backend.
- **`VkBindingOffsets` must be zero**.
- Refused by name: combined texture samplers, inline uniform blocks, 64-bit or three-component half
  vertex attributes, a second push-constant block. NRI has no specialization constants.
- `STRUCTURED_BUFFER` / `STORAGE_STRUCTURED_BUFFER` and `BUFFER` / `STORAGE_BUFFER` tell an SRV from a
  UAV on D3D12.
- **The Descs pin must match SharpNRI's own**; another one restores with NU1608, which
  `-warnaserror` makes an error. The pins are named `SharpNri*PackageVersion` because MSBuild
  property names ignore case and SharpNRI defines `SharpNRI*`.
- **NRI moves only the first slice of a 3D storage texture** (third party): on a device with
  `VK_KHR_maintenance9` the layers report `VUID-vkCmdDraw-None-09600` for slices above 0.
  `SlangComputeCorpusTests.IsNriThreeDimensionalSliceLayout` excuses exactly that.

### Cross-platform behaviour

- **x64 and arm64 builds of Slang's release emit different SPIR-V for `SV_VertexID`** (U17): the two
  builtins it lowers to are created in opposite orders, so the modules are equivalent and never
  equal. Handled: `tools/ci/cross-arch-differences.txt`, checked both ways by `compare-digests.sh`,
  which expects no difference when both architectures' payloads carry the fix (each leg's
  `payload-patches.txt`). Caller's rule with Slang's release: cook on one architecture, or
  content-address per architecture.
- **Crash behaviour has no platform rule** (U2, U3, U4 each differ by platform), so each call is asked
  on every leg.

### Allocator poisoning and crash diagnosis

- The Test step sets `MALLOC_PERTURB_=165`, `GLIBC_TUNABLES=glibc.malloc.tcache_count=0`,
  `MallocScribble=1`, `MallocPreScribble=1`, `MallocNanoZone=0`, so a use-after-free reads poison
  instead of stale data. `MALLOC_PERTURB_` alone misses small blocks (the tcache); `MALLOC_CHECK_` is
  a no-op on current glibc. `The_allocator_poisoning_is_armed_and_reaches_small_allocations`
  asserts it on every leg.
- On a failed leg CI prints the test that started and never finished, the last completed tests and a
  per-class tally; on macOS `tools/ci/macos-backtrace.sh` reads the crash report. A crashed host's
  "reason" is stderr, never the cause.

### Tests and skips

Oracles, each outside the binding:

| Claim | Oracle |
|---|---|
| L0 bytes and signatures match the header | `NativeAbiTests`: a C++ probe compiled against the pinned `slang.h` |
| vtable slot order | `VtableOrderTests`, from the header's declaration order |
| every bound export exists | `NativeExportTests` |
| the pin is what runs | `Build_tag_matches_the_pinned_version` |
| defaults and result codes | `DefaultsDriftTests`, `SlangResultDriftTests` |
| reflection agrees with the code | `ModuleAgreementTests` diffs the corpus against the emitted module |
| reflection agrees with Slang's expectations | `SlangReflectionCorpusTests`, `SlangWalkerCorpusTests` |
| offsets and binding indices work | `SlangComputeCorpusTests` dispatches Slang's compute tests on SharpNRI's validated Vulkan device and compares the readback with Slang's recorded words |
| the projection's pipeline state is valid | `NriDeviceTests`, `NriValidationTests` on validated Vulkan and D3D12 |
| DXIL is signed and loadable | `DxilTests` |
| the whole stack renders | `PixelTests`: SPIR-V and DXIL drawn through NRI on Vulkan and D3D12, every pixel against a CPU reference |
| each target's output is valid there | `TargetValidationTests`: every target's own tool, each also shown broken output it must refuse |
| Slang's enum surface is exercised | `SurfaceCoverageTests` |
| every platform cooks the same asset | the CI `digests` job across legs |
| the reader carries no compiler; the binding knows nothing of the pipeline | `AssemblySplitTests`, from metadata |
| the stored projection is the projection | `NriPackageTests` |
| the loaded parts are the built ones | `VersionGuardTests` |

| per-frame calls allocate nothing | `AllocationTests`, `AllocationCoverageTests` |

Each target's tool is found at run time (`TargetValidators`: PATH, `$VULKAN_SDK/bin`, cargo's bin,
`$CUDA_PATH`, the test output for dxc); a missing one is a skip naming it. SPIR-V and DXIL also run
on devices; GLSL, WGSL, Metal and CUDA have a validator or compiler only; HLSL and C++ are
compile-only.

- **Skip attributes name the capability**: `[NativeFact]` (the payload loads), `[AbiFact]` (a C++
  compiler), `[DxcFact]`, `[NriNoneFact]` / `[NriVulkanFact]` / `[NriD3D12Fact]` (NRI and that
  backend's device), `[ValidatorFact]` (a target's tool), `[PatchedFact]` / `[ReleasePayloadFact]`
  (the payload, Patches), each with its theory form.
- **Platform-keyed skips**: linux-arm64 skips the NRI-backed tests (SharpNRI ships no `libNRI.so`
  for it); macOS skips them by decision.
- **Asserted as wrong, not skipped**: where Slang's release is wrong, the release-payload facts and
  the declared lists say so exactly, checked both ways, so a fix fails a test.
- **Child processes**: `tests/SharpSlang.Prober` runs one question per process; exit 0 completed, 1
  threw, 2 misuse, anything else ended the process. `healthy` runs first.

### CI runners and flakes

- Runners, pinned: `windows-2025-vs2026` (WARP, no Vulkan ICD), `ubuntu-24.04`, `ubuntu-24.04-arm`,
  `macos-15`; the source builds on `ubuntu-22.04` and `ubuntu-22.04-arm` for the glibc floor.
- **Validation layers on linux-x64**: Ubuntu's packaged layer is too old for what NRI chains into
  `vkCreateDevice`; CI takes the 1.4.363 layer from LunarG's SDK tarball (SHA-256 pinned in
  `ci.yml`), caches it and puts it in front with `VK_ADD_LAYER_PATH`. SharpNRI's test device skips
  with an older layer's first error, so the gates below are what notice.
- **linux-arm64 has no Vulkan validation and no dispatch** (no `libNRI.so`); its coverage is the
  compiler, reflection, the ABI and slot oracles, and the cross-architecture digests.
- **lavapipe** (linux-x64): no `VK_DRIVER_FILES` (Mesa renamed its manifest between releases).
- **"Actually ran" gates**, counted from the TRX because a skip is green: the Vulkan validation and
  compute dispatches on linux-x64, the header and corpus oracles on every leg, `NriDeviceTests` on
  win-x64 and linux-x64, `DxilTests` on win-x64, the pixel test, the target validators (35 rows per
  target per leg, none skipped), and with the source-built payload the patched tests (Patches).
- **Validators on the runners**: the Linux legs install `spirv-tools` and `glslang-tools`; naga is
  built once per version and cached (linux-x64); Windows needs nothing installed; macOS uses Xcode.
  No leg has CUDA.
- **Hang bound**: the Test step has a 20-minute timeout, so the diagnostic log names the test.
- **Rate limit**: the job token goes to the tests (`GITHUB_TOKEN`); the header and corpus are cached
  per pin.
- **The unlocked-sharing test was ended by a measurement** (Threads): undefined behaviour has no
  outcome to pin; the prober keeps the probe.

### Actions budget

Actions minutes are budgeted, macOS minutes most of all, and the owner's rules are:

- **Nothing starts by itself on a branch.** A branch is tested by Actions > CI > Run workflow
  (`macos`, `force`, `from_source` inputs). Such a run is not among a pull request's checks, so the
  gate sets a pending commit status "ci" and the `report` job posts the outcome.
- **A branch must be up to date with `master` and green before it merges**; the gate refuses a branch
  behind `master`.
- **Nothing reruns on `master` unless the tree differs from what a branch run tested**
  (`tools/ci/ci-gate.ps1`, matched per job and tree). Docs-only pushes start nothing on `master`.
- **Never two overlapping runs on one head.**
- **macOS on demand and weekly** (Monday, `master`, skipped when the tree already passed it).
- **The workflows**: `ci.yml` (gate, regen, checks, docs, a test job per leg, `native-from-source`,
  digests, report), `checks.yml` (lint, zero-alloc), `regen.yml`, `coverage.yml` (`coverage.ps1
  -Check`, blocks nothing), `release.yml`.
- **"ci" covers the run**: it fails on any job that neither passed nor was skipped by the gate.
- **The payload cache**: `.github/actions/slang-payload` stages `runtimes/<rid>/` from the cache, or
  from Slang's release or the submodule, and saves it before any test. The key
  (`tools/ci/native-payload-key.ps1`) is the git object ids of its inputs, the same on every OS and
  in every workflow, so a payload is made once per input set. A cache hit makes a source-built
  payload cost seconds; a build is about half an hour on the hosted runners.
- Never push what starts a run known to fail.

### The release

Manual, from `master` (`release.yml`). Before starting: pack on Linux as the workflow does, run
`check-packages.ps1`, reproduce `tools/consume`, and see CI green on `master`'s tree.

1. **version**: `tools/ci/release-version.ps1` checks each packed project's `Version` against its
   property, refuses another branch, an existing tag `v<Version>`, missing
   `docs/releases/v<Version>.md` and coverage figures that do not describe the tree; runs
   `descs-version.ps1`; and `ci-gate.ps1 -Workflow release` requires the three test legs, digests,
   docs, lint and zero-alloc green for the tree (or a first-parent commit differing only in docs).
2. **native**: win-x64, linux-x64 (Ubuntu 22.04), linux-arm64 (Ubuntu 22.04 arm) from source through
   the payload action, and the symbol zips.
3. **pack**: the six packages on Linux; a Descs or reader version already on nuget.org is taken from
   there; `check-packages.ps1` and `api-changes.ps1`.
4. **consume** on win-x64, linux-x64 and linux-arm64.
5. **release**: tag, GitHub release (body from `release-body.ps1`), the `.nupkg` files and symbol
   zips; osx-arm64 attaches its zips when its runner turns up.
6. **nuget**: Trusted Publishing after the owner approves the `nuget` environment; skipped while the
   `NUGET_USER` repository variable is absent. Each package pushed alone with `--skip-duplicate`.

- **Preconditions, the owner's**: the repository public, `SHARPSLANG_NATIVE_FROM_SOURCE` set, and on
  nuget.org a Trusted Publishing policy for repository `Nullpoint56/SharpSlang`, workflow
  `release.yml`, environment `nuget`, package ids `SharpSlang` and `SharpSlang.*` on separate lines
  (the glob does not match the bare id); then the `nuget` environment, limited to `master` with the
  owner's approval, and `NUGET_USER`.
