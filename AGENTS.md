# SharpSlang: working notes

For coding agents and human contributors: what the repository is, its rules, how to build and
test, the patch set, the decisions and their reasons, and every oddity measured so far with where
it is handled. Usage and caveats for library users are in `docs/guide.md`; keep the two consistent
when a fact changes. History (how a finding was reached, earlier figures, the pins before this one)
is in git log; report text for each Slang defect is in `docs/upstream.md`.

Measurements belong to Slang v2026.21 (tag commit e73d2689, released 2026-11-04) unless they say
v2026.14.1, the previous pin; a v2026.14.1 figure is marked "re-measure" where nothing at v2026.21
has re-taken it. Source line numbers in Slang are at v2026.21. Local figures come from the
development workstation (Windows 11, NVIDIA GeForce RTX 4070 SUPER) and from WSL2 Ubuntu 24.04 on
the same machine; CI figures name the GitHub-hosted runner and the run. A figure with neither is a
defect: fix it or mark it for re-measurement.

## The repository

C# binding over the Slang shader compiler, plus opt-in shader pipeline packages built on the
binding's public API. One SharpSlang release pins exactly one Slang release (`<SlangVersion>` in
`Directory.Build.props`, an exact pin, not a floor): Slang states its public ABI "is not currently
stable" (`docs/building.md` upstream) and directs redistributors to ship the exact libraries they
built against. .NET 11 / C# 15, xunit.v3 4.0.2 on Microsoft.Testing.Platform.

### Branches

- **State.** One long-lived branch, `master`, the default branch (owner, 2026-11-08), at Slang
  v2026.21. `next` does not exist yet.
- **Direction, once both exist.** `master` pins the latest Slang tag; releases are cut from it only.
  `next` pins a commit of Slang's `master`, moved on purpose. Binding work lands on `master` and is
  merged forward into `next`, then L0 is regenerated there rather than conflicts in `dotnet/Native`
  resolved by hand.
- **Adopting a tag.** Point `slang/` at the tag (`git update-index --cacheinfo 160000,<commit>,slang`,
  the one sanctioned way to stage the pointer), set `<SlangVersion>`, drop the patches the tag
  carries (each test must pass without its patch), re-cut the rest, regenerate L0, run Windows and
  the WSL leg on fresh build trees, and re-measure every figure this file marks as belonging to the
  previous pin.
- **CI** is manual on branches and on `master` reruns only trees no branch run has passed (owner,
  2026-11-07; Actions budget).

- **The reflection objects** (`Core/Reflection/`) are one class per `slang::*Reflection` type, one
  member per `spReflection*` function: parameterless getters as properties named after Slang's
  getter, the rest as methods with Slang's name and argument order (`GetBindingRangeType(index)`).
  They borrow (L1's `SlangReflectionObject`): every member checks the owning program, module or
  entry point and throws `ObjectDisposedException` once it is disposed; two wrappers over one
  pointer are equal. The two that end the process are left out: U1's
  `spReflectionType_GetSpecializedElementCount` and U4's `spReflection_specializeType`; U3's guard
  is `SlangShaderReflection.SpecializeGeneric`'s, a binding guard on the call it protects.
  `SlangType.ElementCount` documents U1 instead (only the layout can tell).
- **No target is chosen for the caller** (owner, 2026-11-08). Every call that reads one target
  takes the index, required: `GetEntryPointCode*`, `GetTargetCode`, `GetEntryPointIdentityHash`,
  `Get*Metadata`, the compile results, `GetLayout`, `FindType`, `RequireType`, `IsSubType`,
  `ToJson`, and in the cooker `Reflect`, `Walk`, `Bake`, `SpecializeGeneric`, `FindFunction`,
  `ResolveOverload`, `GetSpirvEntryPoint`. Required rather than refused on a multi-target session:
  the call then reads as the Slang call it makes and answers the same whatever the session holds,
  where a single-target rule would make one call succeed or throw by configuration, another rule
  to know. `slang.h` gives `getLayout` a default of 0 and none of the code getters one; the
  binding takes neither. With a SPIR-V and a DXIL target the layouts differ per index (a texture is
  binding 1 on SPIR-V and `t0` on DXIL), and a type found by name is the same `TypeReflection`
  from either target's layout (v2026.21, `CompositeTests`).
- **The diagnostics policy stays in L1.** `SlangDiagnostics.Policy` (throw on an error-level
  diagnostic from a successful call) is the guard for U9, where Slang reports degraded output on
  a successful result, and it has to run inside every call that returns a diagnostic blob, which
  only the binding makes. It is the template's "result codes to exceptions with the error text"
  with that one guard, not pipeline policy; the default is an owner decision (Decisions).

- Assemblies: `SharpSlang.Descs` is L0 without `SlangApi.cs` (127 generated files: the enums,
  structs, COM interface structs, IIDs and opaque handles), plus `SlangHeaders.Version` written from
  `SlangVersion` at build time and `SpirvVersion` (`descs/SpirvVersion.cs`: the SPIR-V version as
  Slang's `spirv_1_x` profiles name it, which the binding's `TargetOptions` and the reader's
  `BakedEntryPoint` both carry); `SharpSlang` is `SlangApi.cs` and L1 to L3. The split is by file in
  `NativeSplit.props`, so the two projects cannot disagree about where a type lives. The interface
  structs are in Descs because none of them names the library: their methods call through the
  `lpVtbl` of an object the caller already holds. `SharpSlang` and `SharpSlang.Pipeline` both
  reference Descs, exactly, and neither references the other; Descs references nothing but `System.Runtime` and declares no P/Invoke
  (`AssemblySplitTests.The_descs_assembly_names_no_native_library`, measured from metadata too: 0
  `ImplMap` and 0 `ModuleRef` rows; 89,088 bytes, Release, at 093382b).
- L1: `SlangObject` takes a native reference on its whole ancestor chain and counts its live
  children (Ownership and lifetime); `SlangReflectionObject` borrows; `SlangResult` failures become `SlangException` carrying the call name (`Operation`)
  and Slang's text: the diagnostic blob, or, when a failed call left none, the internal error Slang
  signalled on the calling thread (`slang_getLastInternalErrorMessage`, thread-local and never
  cleared upstream, so attached once per thread per text); an error-level diagnostic on a
  successful call is fatal by default (`SlangDiagnostics.Policy = ThrowOnError`); host callbacks are
  `[UnmanagedCallersOnly]` thunks recovering the receiver from a `GCHandle`, and no managed
  exception crosses into Slang (a throw becomes a failure code; `CallbackBoundaryTests`);
  `SlangGlobalSession.Create` is the version guard and the first call that explains a missing
  library (Pin and payload).
- L2 deliberately does not: add locks (Slang's threading rule is the caller's), dispose children
  for a parent, or hide Slang behaviour behind defaults other than the ones its header declares
  (a DXIL target names its shader model, or Slang picks: `CoreSurfaceTests`).
- A parent refuses `Dispose` while a child it made lives (`SlangObject.LiveChildren`; Ownership
  and lifetime), and no wrapper has a finalizer.
- Escape hatches, in order: the wrappers; the native pointer of each (`NativeHandle` on every
  `SlangObject`, reflection object and extension); the generated vtable structs of
  `SharpSlang.Native`, called through that pointer; `SlangApi`'s P/Invokes.
- Pipeline packages (`SharpSlang.Pipeline*`) use only `SharpSlang`'s public API. The reader has no
  native dependency: a game that ships baked packages carries no compiler.

### Upstream shape

Slang's public C/C++ surface is `include/slang.h` (6,347 lines at v2026.21) plus
`include/slang-deprecated.h` (1,743 lines), which `slang.h` includes. Two shapes:

- **COM-style interfaces.** `ISlangUnknown`'s IID is `IID_IUnknown`. `SLANG_MCALL` is `__stdcall` on
  Windows and empty elsewhere; on 64-bit targets `__stdcall` is a no-op, so the generated
  `delegate* unmanaged[Stdcall]` serves every RID (linux-arm64 and osx-arm64 run it). No vtable
  method takes or returns a struct by value. `SLANG_NO_THROW` is `__declspec(nothrow)` on Windows
  and empty elsewhere, and C++17 makes `noexcept` part of a function type, so a probe has two ABI
  shapes (Generator and ABI).
- **Flat C functions.** The reflection API is flat C (`spReflection*`), declared in
  `slang-deprecated.h`; the C++ reflection classes in `slang.h` declare no virtual methods and are
  inline forwarders to those functions, so the flat functions are the reflection ABI for C++ callers
  too. The deprecation notice at the top of that header is about the legacy compile-request API
  that shares the file.

### Unbound surface

Every unbound function, with its reason, by family. `VtableOrderTests` (each interface's cold
slots, counted and explained), `SurfaceCoverageTests` and the generator's IID check hold the list;
`tools/coverage/BoundSurface` measures it (Coverage), and `_build/coverage/bound.json` names every
unbound slot, export and field.

- **The reflection API is bound whole** but for two: 171 of the 173 `spReflection*` exports, through
  the reflection objects (Layers). `spReflectionType_GetSpecializedElementCount` ends the process on
  the input it exists for (U1; Sizes Slang does not know), and `spReflection_specializeType` ends it
  on Linux for a non-generic type (U4); both are asked only by the prober.
- **The legacy compile-request API**: unbound by decision (owner, 2026-11-08). `IGlobalSession` /
  `ISession` supersede it, and it is generated only because `slang.h` includes `slang-deprecated.h`.
  That is all of `ICompileRequest` (81 slots), `IGlobalSession::createCompileRequest` and
  `ISession::createCompileRequest`, and the 80 flat `sp*` functions of the family: the legacy
  session (`spCreateSession`, `spDestroySession`, `spSessionSetSharedLibraryLoader`,
  `spSessionGetSharedLibraryLoader`), `spCreateCompileRequest`, `spDestroyCompileRequest`,
  `spCompile`, every `spSet*`, `spAdd*` and `spGet*` on a request, `spProcessCommandLineArguments`, `spLoadRepro`, `spSaveRepro`,
  `spExtractRepro`, `spEnableReproCapture`, `spLoadReproAsFileSystem`, `spOverrideDiagnosticSeverity`,
  `spTranslationUnit_addPreprocessorDefine`, `spIsParameterLocationUsed` (the request form of

  `IModule::disassemble`), **coverage tracing** (`slang_writeCoverageManifestJson`,

## Rules

Decided; not reopened as a side effect of other work.

- **Nothing of ours in C or C++.** The binding is managed code over a pinned native build; the
  repository's native content will be the patch set.
- **Every Slang defect found is recorded**, measured, here (Oddities and caveats) and in
  `docs/upstream.md` as report text, filed or not. Filing is the owner's trigger: nothing is posted
  upstream without the owner reading the exact text (`CLAUDE.local.md`).
- **Once the from-source build exists, a Slang defect is patched test first.** The test asserts the
  right answer and is run red against the unpatched build; the patch makes it green. Until then a
  defect is guarded in the binding and its wrong behaviour is asserted as wrong, so the day Slang
  fixes it is a failing test naming the guard to remove. Never a test shaped around a defect or a
  skip with a "to fix" note.
- **A patch is Slang-shaped**: Slang's own coding conventions (`docs/design/coding-conventions.md`,
  `CLAUDE.md` and `.github/copilot-instructions.md` upstream), comments in Slang's declarative
  voice, a regression test under Slang's `tests/`, never a semantic change to an existing call, and
  never a reordered, inserted or removed vtable method or enumerator (Slang's header rules).
- **Third-party defects are worked around and recorded, not patched**: drivers, lavapipe, the
  Khronos layers, dxc, the .NET runtime.
- **The library knows nothing about any consumer.** No project, test, package or document names an
  engine or product of ours. Repository and package names carry no engine name.
- **No vendor runtime shipped whose licence a library cannot meet.** dxc reaches applications
  through `SharpSlang.Dxc`, which depends on Microsoft's package and copies from it (owner,
  2026-10-14).
- **Claims are measurements.** Ownership, refcount and platform claims are measured and pinned by a
  test asserting the measured value, never derived from COM convention, documentation or one
  platform. `addRef` then `release` reports a refcount without changing it.
- **Oracles outside the binding** for every claim (the table under Tests and skips). The binding's
  description of itself is not an oracle, and Slang describing itself is a weak one.
- **No meaningless tests.** A skip names the missing capability (a library, a compiler, a device
  feature, a file). A skip keyed on a platform quotes a measured defect or names an owner decision.
  A question whose answer may end the process runs in the prober, never in the shared test host.
- **No stale figures.** A figure names its commit and hardware; tooling discovers the machine at run
  time.
- **No finalizers.** A forgotten `Dispose` leaks; it never corrupts (Ownership and lifetime).
- **Zero allocation per frame applies to `SharpSlang.Pipeline`** (owner, 2026-11-08): every lookup a
  renderer makes after load allocates nothing, measured. The compiler binding is exempt: it runs at
  cook time.
- **Don't flood CI.** Verify locally on every platform the machine has (Windows, WSL) before a push;
  start one run per head, only when it is expected to pass (Actions budget).
- **Code cites these notes by heading anchor**, `AGENTS.md#<anchor>`, and nothing else (no section
  numbers). `tools/ci/check-docs.sh` fails on an anchor with no heading, so renaming a heading
  means updating the comments that cite it in the same change. Tests that pin a figure stated here
  read this file (`DocumentedFactsTests.Documents("AGENTS.md", ...)`), so a figure changes here when
  its test changes.
- `slang/` and `patches/` are not changed as a side effect of other work. Stage by path.

### Native build

```powershell
git submodule update --init --recursive slang      # Slang at the pinned tag, with external/ (1.4 GB)
pwsh tools/build-native.ps1 -Rid win-x64           # or linux-x64 / linux-arm64 / osx-arm64, on that OS
```

It checks `slang/` against `<SlangVersion>` (fetching the tag ref if the checkout has none) and its
nested submodules, applies `patches/`, configures with Ninja into `_build/<rid>/`, checks each
library's imports against exact lists, stages `runtimes/<rid>/` through an allowlist, and prints
what it staged. Without a staged library the binding's build stops with `SHARPSLANG001` and this
command; `-p:SharpSlangRequireNative=false` skips that (lint does).

| Flag | Meaning |
|---|---|
| `-Rid` | `win-x64`, `linux-x64`, `linux-arm64`, `osx-arm64`; default the host. Host OS and architecture only, no cross-compiling |
| `-StandardModules` | `All` (default, the release's set) or `WithoutNeuralNumerics` (Native packages); staging only |
| `-WithGlslModule` | also stage `slang-glsl-module` (GLSL source input) |
| `-AllowNewerGlibc` | Linux: stage a build above the pinned glibc floor instead of failing, for local test builds (Pin and payload) |
| `-WithoutPatches` | reverse any applied patch, apply none, build into `_build/<rid>-unpatched/`: the payload a patch's test runs red against, and the Slang-bump check's (Patches); never one to pack |
| `-WithSlangTests` | also build Slang's test tools (tests, slang-rhi, slangc, slangd) into `_build/<rid>-tests/`, patches applied, and run each patch's `SLANG_UNIT_TEST` with `slang-test`; stages nothing (Patches) |
| `-Configuration` | CMake configuration, `Release` by default |
| `-Clean` | delete `_build/<rid>/`, downloads included, before configuring |

Toolchains: Windows needs Visual Studio 2022 with the C++ x64 tools (the script enters its developer
shell and uses the Ninja it ships) and Python 3 (found by the script, since a broken `python` on
PATH is otherwise taken); Linux needs GCC, CMake 3.22 or newer, Ninja and Python 3, and builds the
payload on Ubuntu 22.04 for the glibc floor; macOS needs Xcode's AppleClang and Ninja. Clean builds
on the workstation (Ryzen 7 9700X, 16 threads, f55670e and 23be068): win-x64 2 min 55 s (configure
10 s, 21.6 thread-minutes of Ninja edges), linux-x64 under WSL 4 min 52 s (43.5 thread-minutes,
1137% CPU, 2.4 GB peak RSS, a 2.9 GB tree). A reconfigure with an unchanged key runs offline in 2 s.

### Lint

The SDK's own analyzers and no analyzer package: `AnalysisLevel` `latest-recommended`,

packages, allocation). Both commit-relative: run them on the committed tree. A planted unused
`using` fails lint with IDE0005 (workstation, branch `sharpslang-workflows`).

- **The generated layer is linted too, and was not.** ClangSharp's `[assembly: GeneratedCode]`
  (`GeneratedCode.cs`) made the SDK's analyzers treat the whole assembly that compiled it as
  generated code and report nothing in it: SharpSlang.dll, hand-written layers included. Measured
  when L0 moved to SharpSlang.Descs: SharpSlang, no longer compiling it, reported 282 findings (279
  CA1401 on `SlangApi`'s public P/Invokes, CA1305 in `GenericArgument.ToString`, CA1816 in
  `SlangObject.Dispose`, one IDE0005); Descs, with `--generate generated-code=none`, 260 (143

  tests are not built: they compile a path into a preprocessor definition, which CMake drops when
  the path holds a `#`, as this checkout's does.

- **Applying.** `build-native.ps1` applies `patches/*.patch` in name order and skips a patch already
  applied, by a reverse check with `-C0`.
- **Cutting.** A patch is a `git diff` against the tag with a prose header. A patch to a file an
  earlier patch touches is cut from a scratch clone with the earlier ones committed. Every patch
  applies cleanly in order and each also alone.
- **Re-cutting on a new tag.** Apply in order onto the tag in a scratch clone, re-cut each with the
  earlier ones committed, check order, alone and the `-C0` reverse check; drop the ones the tag
  carries, each test passing without its patch.

## Decisions

- **CI stays on Slang's release payload until the repository is public** (owner, 2026-11-08). The
  test legs stage `fetch-native.ps1`'s payload while the repository variable
  `SHARPSLANG_NATIVE_FROM_SOURCE` is unset, and it stays unset; setting it to `true` is the whole
  switch (`native-from-source` builds, the legs restore its payload; Patches). What it means until
  then: CI does not verify the patches. Their tests skip there, naming the patch, so every patch
  batch is verified locally against our build, on Windows and on Linux under WSL (Patches). A
  release packs payloads built from source, patches applied, whatever the variable says. One run
  can take the source-built payload without the variable: the manual run's `from_source` input
  (owner, 2026-11-11), for checking the hosted runners' source builds (linux-arm64 has no other
  place to build) and the patched tests on every leg before a release.
- **Name and repository: SharpSlang** (owner, 2026-11-08). No package or repository had the name
  that day. No engine or product name in it.
- **Packages: `SharpSlang`, `SharpSlang.Descs`, `SharpSlang.Dxc`, `SharpSlang.Pipeline`,
  `SharpSlang.Pipeline.Bake`, `SharpSlang.Pipeline.NRI`** (owner, 2026-11-08). The pipeline packages
  fill a new template slot, `<Binding>.<Feature>`: opt-in layers that use only the binding's public
  API (owner, 2026-11-08). The reader is separate from the cooker so a shipped game carries no
  compiler; the NRI projection is separate so the reader does not pull NRI's descs.
- **The binding knows nothing of the pipeline** (owner, 2026-11-08: the pipeline packages use only
  the binding's public API, no `InternalsVisibleTo`). The walker and the baker are
  `SharpSlang.Pipeline.Bake`, rebuilt on the L2 reflection objects, and `SharpSlang` references
  `SharpSlang.Descs` alone (Layers).
- **The Vulkan projection is dropped** (owner, 2026-11-08): the engine renders through NRI only.
  `SharpSlang.Vulkan` (`ToVulkan`, the mirrored Vulkan enums, `VulkanEnvironment`, specialization
  packing, `VulkanWorkgroupSize`) and Vortice.Vulkan are gone, and the raw-Vulkan validation oracle
  runs on SharpNRI's validated Vulkan device through the NRI projection. **The engine projects at bake time**
  (owner, 2026-11-08), so `SharpSlang.Pipeline.NRI` runs in the cooker.
- **Versions: the major is the Slang version as a fixed-width YYYYRRP** (owner, 2026-11-08):
  v2026.21 is `2026210.B.F`, v2026.18.3 is `2026183.B.F`. Slang versions are not one integer, and a
  four-part `YYYY.RR.P.B` would make version tooling read a Slang bump as a minor change; with the
  encoding every Slang release is a new major, which it is (the ABI is unstable). Within one Slang
  version, a breaking binding change moves B, a fix moves F; beta while the API may change. The
  assembly and file versions cannot hold the major (16 bits a part) and are `YYYY.RRP.B.F` (Pin and
  payload).
- **No `SharpSlang.Testing`** (owner, 2026-11-08): there is no device to wrap; SharpNRI.Testing
  provides the devices the pipeline tests use.
- **Each compile target is held to its strongest outside oracle** (owner, 2026-11-08): a pixel or
  readback test where a runnable device exists (SPIR-V on Vulkan, DXIL on D3D12, both through
  SharpNRI; "every backend" means those two) and validators for the rest where one exists,
  compile-only otherwise and named as such, on the condition "make sure we truly try our best to
  test as much as possible". The table under Tests and skips is the result.
- **The legacy compile-request API and the language server are unbound** (owner, 2026-11-08;
  Unbound surface).
- **Zero allocation per frame applies to `SharpSlang.Pipeline`, not the binding** (owner, 2026-11-08).
- **Default branch `master`; going public, the rulesets and nuget.org Trusted Publishing are the last
  step** (owner, 2026-11-08). Until then the repository is private on GitHub's Free plan, which
  answers branch protection and rulesets with "Upgrade to GitHub Pro or make this repository public".
- **CI is manual on branches; `master` reruns only untested trees; a "ci" commit status gates merges;
  macOS on demand** (owner, 2026-11-07; Actions budget), **and weekly; nothing in a release waits
  for it** (owner, 2026-11-08): no package carries the osx-arm64 library, which the release attaches
  as a zip when its runner turns up.
- **Upstream filing is the owner's trigger** (owner, 2026-11-08, from the template; the earlier rule,
  owner, 2026-08-10, was never to file without explicit say-so, because the owner could not vouch for
  AI-assisted debugging results and would not spend maintainers' time on them).
- **Pure managed P/Invoke, L0 generated by ClangSharp in C++ mode, everything above hand-written.** L0
  is the only layer that churns on a Slang bump; generating it makes a bump a reviewable diff. The
  generator is unsafe above L0: its one silent-corruption output (the `Thiscall` callbacks) was in
  the host-callback layer. ClangSharp is pinned (21.1.8.4) because its output is the compared input.
- **dxc by dependency, not by redistribution** (owner, 2026-10-14). Microsoft's `LICENSE-MS.txt` in the
  DirectXShaderCompiler GitHub release forbids a stand-alone offering of the files, which a
  payload-only package is; `SharpSlang.Dxc` carries no binary and the consumer takes Microsoft's
  terms by restoring Microsoft's package.
- **Reflection is projected to an immutable managed snapshot, walked once, never proxied.**
  `SlangReflection*` and everything reachable from it is owned by the `IComponentType` that produced
  it, so a proxy is a use-after-free presenting as corrupt bindings; a snapshot is serializable, so a
  shipped game needs no compiler (Reflection snapshot).
- **No finalizers; every wrapper holds its whole ancestor chain** (Ownership and lifetime).
- **Packages stay unpublished until the owner's last step** (owner, 2026-11-08): versions are
  `2026210.0.0-beta.1`; going public and nuget.org come last.
- **Slang's standard modules ship in `standard-modules/<rid>/`, copied beside the compiler by build
  targets** (2026-11-08, the packaging step): the template forbids a subfolder under `native/`,
  which NuGet flattens, and Slang reads the modules only from a folder of one fixed name beside the
  library it runs from (Native packages). Copying keeps them per RID, as Slang's release builds
  them.
- **`SessionOptions.ExperimentalFeatures`** (2026-11-08, the packaging step): Slang's
  `-experimental-feature` on the session, the one switch without which no standard module the
  package carries can be imported through the binding. Off by default, as in Slang.
- **Notices beside the application, opt-out `SharpSlangCopyLicenses=false`** (the template's rule):
  `licenses/SharpSlang/<rid>/`, as SharpNRI's `licenses/SharpNRI/<rid>/`.
- **Trimming and Native AOT declared on every shipped assembly**, and the layout's JSON source
  generated (Native packages): a cooker published with Native AOT warns nothing.
- **SharpNRI from nuget.org at exact versions** (owner, 2026-11-07): `SharpNRI` and `SharpNRI.Testing`
  at `SharpNriPackageVersion` (191.0.0-beta.4) for the tests, `SharpNRI.Descs` at
  `SharpNriDescsPackageVersion` (191.0.0-beta.1) for the projection. Sibling-checkout mode and the
  private feed are gone. `SharpNRI.AgilitySDK` is not used: in Release it silently disables D3D12
  validation, which the D3D12 tests depend on.
- **Pins are exact.** A Slang bump is a breaking change; a `SharpNRI.Descs` bump can move a field.
- **Linux runners pinned to Ubuntu 24.04**: the lavapipe steps install by package name, and the
  allocator notes are measurements of glibc 2.39. Moving the image is a decision.
- **The default diagnostics policy throws on an error-level diagnostic from a successful call**, and
  `GlobalSessionOptions.RequireSpirvOptimizer` and `RequirePinnedSlangVersion` default on: Slang
  reports a missing optimiser once, on a success (Companion libraries and dxc).

## Oddities and caveats

Each entry: the fact, the evidence, where it is handled, and the caller's rule. "U<n>" names a report
in `docs/upstream.md`.

### Generator and ABI

- **ClangSharp's residue, all fixed in `tools/generate-native.ps1` only.** At v2026.21 the script
  produces 128 files in namespace `SharpSlang.Native`, LF throughout, with 279 `DllImport`s and 383
  vtable call sites, 0 errors and 0 warnings on `net11.0` under the lint configuration; regenerated
  with 21.1.8.4 at 093382b it equals the committed files byte for byte. Each workaround, and the
  failure it prevents:
  - ClangSharp's redundant `using System;` (33 files; `ImplicitUsings` makes it global) is removed,
    so the generated layer is lint-clean.
  - No `[assembly: GeneratedCode]` (`--generate generated-code=none`; `GeneratedCode.cs` is no longer
    written): with it the analyzers treated the whole assembly as generated and linted none of it
    (Lint).
  - ClangSharp's COM-name twins removed: for each of the 28 interfaces deriving `ISlangUnknown` it
    writes `QueryInterface(Guid*)`, `AddRef()` and `Release()` beside Slang's `queryInterface`,
    `addRef` and `release` slots (84 methods, CA1708). They forward to the slots, which stay, and
    nothing in the repository called them. `slang.h` declares them inline on `ISlangUnknown` "to
    allow the above operations to be called using their traditional COM names".
  - `[Obsolete]` on the two `SLANG_DEPRECATED` slots (`IGlobalSession::createCompileRequest`,
    `addBuiltins`) gets a message (CA1041); `SlangTerminatedChars`' fixed-buffer indexer is written
    as an expression body (IDE0026).
  - `struct Attribute` shadows `System.Attribute` and broke every generated helper attribute: remapped
    to `SlangAttribute` (`--remap-type`).
  - The 12 C++ reflection veneer types (`TypeReflection`, `TypeLayoutReflection`, `ShaderReflection`,
    ...) do not translate (C++ `this` is a pointer, C# struct `this` is a value) and were most of the
    errors: excluded and declared as empty opaque structs in `_OpaqueReflectionHandles.cs`. Nothing
    is lost; the flat functions they forward to are bound.
  - `SLANG_COM_INTERFACE`'s constexpr GUID becomes `new byte[8]` in a fixed buffer:
    `getTypeGuid` excluded, the IIDs parsed out of `slang.h` into `_InterfaceGuids.cs`, and the
    script throws if a generated interface has no IID (`ICompileRequest` excepted: it predates the
    COM conversion).
  - Callback function-pointer typedefs come out `unmanaged[Thiscall]`; they are plain C callbacks,
    and one is `ISlangFileSystemExt::enumeratePathContents`. Rewritten to `Cdecl`: 7 sites at
    v2026.21. Had it compiled, it would have been a silent ABI mismatch.
  - Three inline helpers doing pointer arithmetic on `this` (`ISlangSharedLibrary`,
    `SlangTerminatedChars`, `VMExecInstHeader`): rewritten with `Unsafe.AsPointer`.
  - `SpecializationArg.Kind.Type` collides with `System.Type` under `ImplicitUsings` through a
    generated `using static`: the using is dropped and the uses qualified.
  - `createGlobalSession` excluded: its desc has C++ default member initializers; L1 writes the
    six-line helper (Descriptor defaults and result codes).
  - `spReflection_GetSession` and `slang_getEmbeddedCoreModule` are the two functions in the
    headers with C++ linkage (`slang-deprecated.h:1084`, after the `extern "C"` block closes at
    1080; `slang.h:6126`, without the `SLANG_EXTERN_C` its neighbours have). ClangSharp binds them
    by MSVC mangling, which can only resolve on Windows (`EntryPointNotFoundException` on Linux):
    excluded, and `NativeExportTests` catches their return. U11.
  - Every removal, in one place: the 12 veneer types and `getTypeGuid` (above), `createGlobalSession`,
    the two C++-linkage functions, the 84 COM-name twins, `GeneratedCode.cs`, and `using System;`.
    The step that rewrote nested enum mirrors in `TypeReflection.cs` and `DeclReflection.cs` to
    `: uint` is gone: those files are not generated (their types are veneer), so it had nothing to
    act on.
- **C++ mode, and no enum is erased.** `slang.h` does not parse as C: with `--language c --std c17`
  ClangSharp fails on `bool` (`slang.h:621`), `constexpr` (`:825`) and `namespace` (`:1040`) and
  writes nothing (v2026.21). In C++ mode every parameter, field and return the header declares
  with an enum type is that enum in L0, and `generate-native.ps1` fails a regeneration where an
  enum name in `[NativeTypeName]` sits on an integer: 58 enums, 0 erased at v2026.21. The integer
  flag types (`SlangTargetFlags`, `SlangCompileFlags`, `SlangDiagnosticFlags`,
  `CompileCoreModuleFlags`, `SessionFlags`) are integer typedefs in the header too, with their
  values in anonymous enums (constants on `SlangApi`), and no site uses a `Slang*Integral` typedef.
- **Header comments as XML docs** (`tools/generate-native-docs.ps1`; its header says what attaches
  to what). At v2026.21: 44 types, 437 members and 242 vtable slots documented (inherited slots
  count once per interface that repeats them), 151 `<param>` and 64 `<returns>`, 759 `<summary>`
  in L0 against 36 before (the IIDs and the helper attributes). Slang documents most enums above
  their integer typedef (`typedef ... SlangStageIntegral; enum SlangStage : SlangStageIntegral`), so
  such a comment goes to the enum. `<param>` is written only when the names are exactly the
  generated parameters (CS1572, CS1573 under `-warnaserror`); otherwise they stay as text. Not
  carried, by construction: the C++ veneer's methods (their types are excluded) and the excluded
  functions; `-Verbose` on the docs script lists them (15 at v2026.21).
- **ClangSharp mechanics.** It exits non-zero on macro-translation warnings after generating
  successfully, so the script checks the file count instead. Only `slang.h` is passed as `--file`;
  passing `slang-deprecated.h` too parses it twice (redefinition errors), so it is in `--traverse`
  only. It emits `DllImport`, not `[LibraryImport]`; every signature is blittable, so this costs no
  marshalling.
- **The generator version is part of the input.** ClangSharp 22.1.8 writes
  `NativeTypeName("slang::IBlob **")` where 21.1.8.4 writes `"IBlob **"`, so an unpinned install
  reported L0 out of date for an unchanged header (00a1358). `regen.yml` installs 21.1.8.4
  on the image's .NET 10 SDK; move it together with the version the script states.
- **Compiling is not correctness: the ABI oracle.** A wrong offset, size, bitfield packing or
  parameter list compiles, resolves and dispatches, and `regen.yml` cannot see it (it
  compares the generator with itself). `NativeAbiTests` generates a C++ probe from the C# metadata,
  compiles it against the pinned `slang.h` and compares 51 struct sizes, 116 field offsets, 2
  bitfield accessors (exact bytes written) and 510 signatures, 279 free functions and 231 vtable
  methods, as `static_assert`s. Signatures of vtable methods are reachable through
  pointer-to-member types.
- **Slot order cannot be probed**: clang lays out a vtable only for a class it emits one for, and
  Slang's interfaces are pure-abstract with no key function (`-fforce-emit-vtables` does not help).
  `VtableOrderTests` derives all 374 slot indices from the header's declaration order and compares
  them with the `lpVtbl[n]` each generated method calls. 246 of the 374 slots are never called by the
  binding, so these are the only checks on them.
- **Both oracles read `dotnet/Native/*.cs` as text**: `VtblIndexAttribute` and
  `NativeTypeNameAttribute` are `[Conditional("DEBUG")]`, absent from the Release build CI runs, so
  a reflection-based check would find nothing and pass.
- **Two ABI shapes.** `SLANG_NO_THROW` is `__declspec(nothrow)` on Windows and empty elsewhere, and
  C++17 makes `noexcept` part of a function's type, so a probe compiled only on Windows checks one
  shape. Compile both (`-DSLANG_NO_THROW=` gives the other) before calling a probe change verified
  (72a5010).

### Descriptor defaults and result codes

- **ClangSharp drops C++ default member initializers without a warning** (14 descriptor structs at
  v2026.14.1; `DefaultsDriftTests` holds the current set).
  Zero-initialised descs compile and mis-compile every shader: `SessionDesc.defaultMatrixLayoutMode`
  is `ROW_MAJOR` (1) in C++ and 0 (`UNKNOWN`) zeroed; `TargetDesc.flags` is
  `GENERATE_SPIRV_DIRECTLY` in C++ and 0 zeroed (SPIR-V via glslang); `structureSize`, which Slang
  uses to version the struct, is 0 zeroed. Handled: `dotnet/Defaults.cs` factories,
  `DefaultsDriftTests` re-reads the pinned header and fails on a changed default, and two tests pin
  the two concrete cases. Caller's rule: never construct a Slang descriptor with `new`; start from
  `Defaults.Create*()`.
- **Result codes are function-like macros** (`SLANG_MAKE_ERROR(fac, code)`), which libclang does not
  evaluate, so L0 has none. `dotnet/SlangResult.cs` transcribes them by hand;
  `SlangResultDriftTests` re-reads the header.

### Pin and payload

- **The payload must be the pinned release.** `SlangGlobalSession.Create` compares
  `spGetBuildTagString` with `SlangGlobalSession.PinnedBuildTag` and throws
  `SlangVersionMismatchException` naming both; `Build_tag_matches_the_pinned_version` ties the pin
  to `Directory.Build.props`. A payload with a reordered interface links, calls, and calls the wrong
  function, so this is not defensive. The realistic way to hit it: bump `<SlangVersion>` without
  re-fetching. `RequirePinnedSlangVersion = false` opts out deliberately. The message names the
  loaded library's path (`SlangVersionMismatchException.LibraryPath`): from the process module list, and on Unix from `dladdr` on one of the library's exports when the list does not name it, which on the macos-15 runner it did not (run 42475073038, 2026-11-08).
- **The loaded Descs must be the ones SharpSlang was built with**, checked first in `Create`
  (`Interop/SlangVersionCheck.cs`, SharpNRI's `NriVersionCheck`): the loaded `SharpSlang.Descs`'
  `SlangVersion` metadata against SharpSlang's, and its package version (the informational version
  without `+<commit>`) against SharpSlang's `SharpSlangDescsVersion` metadata. Not covered by the
  opt-out: another release's descs misread values whatever the native library is. A direct reference
  to another Descs version wins NuGet's restore with only NU1608, so the packed
  `buildTransitive/SharpSlang.targets` fails that build first (`SHARPSLANG005`, the resolved version
  read from `project.assets.json` against `SharpSlangDescsDependency` in the packed props).
  `VersionGuardTests` drives the three refusals with the wrong values and builds temporary projects
  for `SHARPSLANG004` and `SHARPSLANG005`; neither run-time mismatch was provoked with a real second
  Descs assembly or Slang payload.
- **Versions, twice** (SharpNRI's names): `Slang.SlangVersion` and `SlangHeaders.Version` are
  constants, compiled into the caller; `Slang.BindingVersion`, `BindingSlangVersion`,
  `DescsVersion` and `DescsSlangVersion` read the loaded assemblies. `PinnedBuildTag` is
  `BindingSlangVersion`.
- **A package major of 2026210 does not fit an assembly version.** Each of its four parts is 16 bits,
  and the SDK's default assembly and file version, the package version's numeric part, failed the
  compile: CS7034 "The specified version string '2026210.0.0.0' does not conform to the required
  format" (SDK 11.0.100-rc.1.26425.128, the tree of 093382b without the split). `Directory.Build.targets` splits the
  major where the encoding joins it: package `2026210.B.F` is assembly and file version
  `2026.210.B.F`. The informational version stays the package version, and that is the one the
  guard reads. `SHARPSLANG004` fails a packable project whose `Version` does not start with
  `SlangVersion`'s encoding, or a `SlangVersion` with none (a patch above 9).
- **A missing `slang-compiler`, explained** (`Interop/NativeLibraryHint.cs`). The first calls an
  application makes into Slang (`Create`, `BuildTag`, `RequirePinnedVersion`, `HashString`) catch the
  runtime's `DllNotFoundException` and throw one naming the file, the RID, the directories looked in
  (`NATIVE_DLL_SEARCH_DIRECTORIES` as the host passed it, and SharpSlang.dll's directory) and where the
  library comes from, the runtime's inside. Measured end to end by
  `ProberTests.Without_slang_compiler_the_failure_names_the_file_the_rid_and_where_it_was_looked_for`
  (the prober's output copied without the compiler, run by the dotnet host from another directory).
  A `ResolvingUnmanagedDll` handler is registered on SharpSlang's load context and only records the
  miss, which the message reports: it never returns a handle and never throws, because the event
  stops at the first handler that does either, and SharpNRI's handler, which threw, kept an
  application's later handler from running (reported downstream; SharpNRI's notes). No DllImport
  resolver either: there is one per assembly and it is the application's.
  `A_handler_registered_after_SharpSlangs_still_runs` holds the chain. The other flat exports throw
  the runtime's own exception. `CompanionLibraries.Preload` resolves the compiler the way the
  DllImports do and, when that fails, preloads nothing and leaves the failure to the explained call.
- **The payload says where it came from**: `runtimes/<rid>/payload.json`, beside `native/` and not
  packed. `fetch-native.ps1` writes `source: release` and the archive; `build-native.ps1` writes
  `source: build`, the Slang commit and each patch applied with its SHA-256; both the SHA-256 of the
  compiler staged. `NativePayloadTests` requires it, the compiler's hash to match the staged file and
  the copies in the test and prober output directories, and a build's patch list to be exactly
  `patches/` (a build from before a patch was added, or `-WithoutPatches`, fails there). The tests of
  patched behaviour run or skip by it (Patches). A payload copied into `runtimes/<rid>/` with its old
  timestamps is not copied into the output directories by an incremental build: the tests then load
  the previous library, and `The_library_under_test_is_the_one_staged` fails naming it (measured
  swapping a patched and the release payload on win-x64). `fetch-native.ps1` stages the archive's
  timestamps, so after a source build run the next build with `--no-incremental`.
- **The library is `slang-compiler`** (renamed from `slang` in v2025.21 because the S-Lang library of
  that name is preinstalled on Linux distributions). The `slang.dll` proxy and the Unix symlinks are
  removed upstream at the end of 2026; the binding has bound `slang-compiler` throughout.
- **Release archive layout**, found by looking: Windows keeps libraries in `bin/`, Linux and macOS
  in `lib/`; Unix libraries carry versioned names (`libslang-compiler.so.0.2026.21`,
  `libslang-glslang-2026.21.so`); `Expand-Archive` on Windows writes symlinks as ~32-byte text stubs,
  so staging matches by glob and takes the largest file.
- **One name per library, and not the same rule for both** (35d7678, linux-x64, v2026.14.1, full
  suite with each copy held aside): without the versioned compiler copy 520 passed, 1 skipped (the
  `DllImport("slang-compiler")` resolves the plain name); without the versioned glslang 361 failed
  (Slang `dlopen`s `slang-glslang-<version>`, `slang-glslang-compiler.cpp:590-595`). Staging both
  names had cost 38.8 MB of an 83 MB linux-x64 payload. `fetch-native.ps1` stages the plain
  compiler name and the versioned glslang name.
- **Licence files are staged beside `native/`, not in it**, and as `LICENSE.txt`: NuGet treats an
  extensionless `PackagePath` as a directory (the first pack produced
  `runtimes/win-x64/LICENSE/win-x64/LICENSE`), and a `PackagePath` whose extension differs from the
  source file's as one too (the repository's `LICENSE` packed as
  `licenses/win-x64/SharpSlang/LICENSE.txt/LICENSE`, so the pack copies it to
  `obj/licenses/LICENSE.txt` first). The pack moves them to `licenses/<rid>/` (Native packages).
  Staging clears everything beside `native/` first; a rename once left the old name staged and
  packed.
- **A packaging glob once dropped the host RID from the package** (its files matched both the
  Content and None globs and `Pack="false"` won); the package restored and failed with
  `DllNotFoundException`. CI's "Package contains the host RID's payload" step checks it.
- **The standard modules are loose files** beside the compiler (`slang-standard-module-<version>/`);
  the core module is embedded, but any other `import` resolves there, and only there: from a folder
  NuGet flattened the import fails with `E00001` (Native packages has the measurement and the
  layout). Every one is `[ExperimentalModule]`: `SessionOptions.ExperimentalFeatures`, or `E00104`.
- **The Linux payload has a glibc floor, set by the build host.** The release needs at most
  GLIBC_2.34 and GLIBCXX_3.4.29 on linux-x64 and linux-arm64 (its version-needs sections,
  `readelf -V`, v2026.21), so it loads on Ubuntu 22.04. Built from source on Ubuntu 24.04 with GCC
  13.3, both libraries need GLIBC_2.38 and GLIBCXX_3.4.32 (`__isoc23_strtol`, `__isoc23_strtoll`,
  `fmod`, `std::ios_base_library_init`, `basic_string::_M_replace_cold`) and would not load on 22.04
  or Debian 12. Handled: `Directory.Build.props` pins the floor (`LinuxGlibcFloor`,
  `LinuxGlibcxxFloor`); `build-native.ps1` prints the floor it produced and refuses a build above the
  pin, saying why, unless `-AllowNewerGlibc`; `NativePayloadTests` fails on a staged library above
  it unless `SHARPSLANG_ALLOW_NEWER_GLIBC=1`; CI builds Linux on ubuntu-22.04. Measured at 00401a8
  under WSL: without the switch the script exits 1 with "glibc floor of this build: GLIBC_2.38,
  GLIBCXX_3.4.32 (pinned: GLIBC_2.34, GLIBCXX_3.4.29)"; with it the test fails naming each library,
  with the variable it skips, and with the release payload it passes. Raising the pin is a decision.
- **A library staged from Slang's build tree searched the working directory.** CMake gives the
  build-tree libraries `RUNPATH "$ORIGIN/../lib:$ORIGIN:"`; the trailing empty entry made glibc add
  `glibc-hwcaps/x86-64-v4:...:` and an empty entry, paths relative to the working directory, to the
  search (`LD_DEBUG=libs`, linux-x64, the build of f55670e, before 23be068), so a same-named library there would
  be found first. The release carries the install RPATH, `$ORIGIN/../lib:$ORIGIN`. Handled:

### Ownership and lifetime

- **`ISession::loadModule*` returns a borrowed pointer.** Every other Slang call that hands out an
  object gives the caller a reference; module loading does not (the session retains its modules,
  which `getLoadedModuleCount` / `getLoadedModule` enumerate), and `slang.h:4640-4656` says nothing
  about it. Releasing it over-releases: glibc aborts (`free(): corrupted unsorted chunks`); the
  Windows heap tolerated it, green from the first commit until the first Linux run. U12. Handled:
  `SlangModule`'s constructor takes its own reference on adoption. Documented by 0007 in `slang.h`
  (`HeaderDocumentationTests`); the behaviour is Slang's contract and stays.
- **A child does not retain its session.** `ISession` retains `IGlobalSession`; `IModule` does not
  retain `ISession`, and neither does a linked program (v2026.14.1, refcounts by `addRef`/`release`:
  session 1 after `LoadModule`, 1 after `Link`). Releasing outermost first destroyed a session under
  a live module; only macOS faulted.
- **Slang destroys the global session inside `~Linkage` when the Linkage holds the last reference,**
  and the two AST arenas double-free a `WitnessTable` (macOS, v2026.14.1, from the crash report:
  `free_small` "Incorrect checksum for freed object" under `Slang::WitnessTable::~WitnessTable` <
  `RootASTBuilder::~RootASTBuilder` < `Linkage::~Linkage`). A refcount-correct release order is
  enough to reach it. U13. Handled: every wrapper holds a native reference on its whole ancestor
  chain, released nearest first, so an ancestor is destroyed after its descendants and never inside
  one of their destructors. `The_global_session_is_never_destroyed_from_inside_the_linkage` asserts
  the invariant as a number one release before the fatal one, so it fails on Windows;
  `Every_child_holds_a_native_reference_to_its_owner` asserts the deltas; the prober's
  `dispose-outermost-first` runs the teardown out of process on every leg. Since a parent refuses
  `Dispose` while a child lives (below), the outermost-first order that reached the crash is
  refused before any release, and the prober asserts the refusals and then the innermost-first
  teardown. Whether Slang still crashes without the chain at v2026.21 is not measured: re-measure.
- **No finalizers.** The GC finalizes in arbitrary order, and a finalizer could release a module
  into a session whose allocator has gone. A forgotten `Dispose` leaks until exit. Double dispose is
  a no-op, also concurrently; use after dispose throws `ObjectDisposedException`.
- **A parent refuses `Dispose` while a child it made lives** (the template's rule, SharpNRI's
  `NriDevice`): `SlangObject` counts the wrappers created with it as owner (`LiveChildren`: a
  global session's sessions, a session's modules and programs, a module's entry points, a
  program's code blobs, metadata and compile results) and throws `InvalidOperationException`
  naming the count, leaving the object alive and usable. `An_owner_refuses_Dispose_while_the_things_it_owns_live`
  holds it. A forgotten child keeps its parent from disposing: a leak of both, never corruption. Caller's rule: dispose children first;
  `using` declarations in creation order do it.
- **Borrowed reflection objects check their owner on every read** (`SlangReflectionObject`): a
  `SlangTypeLayout` read after its program's `Dispose` throws `ObjectDisposedException` instead of
  reading freed memory. They are not children: there is nothing of theirs to release first.
- **A host filesystem must outlive the session**: Slang holds the pointer for the session's
  lifetime, and freeing it under a live session would hand Slang freed memory on its next load.
  `SlangFileSystem.Dispose` refuses while a session created with it lives (`LiveSessions`, the
  binding's own count); Slang's own count on it (`NativeReferenceCount`) is
  measured beside: one more while a session holds it, back to 1 when the session goes
  (`A_file_system_refuses_Dispose_while_a_session_holds_it`). Returning null from a provider is a
  miss and Slang keeps searching; a throw becomes a failure code at the boundary.
  `CallbackBoundaryTests` drives every slot with a null `this`, a null out-parameter and a throwing
  provider.

### Reflection snapshot

- **An unlinked composite reflects**: `SlangComponentType.GetLayout` on the composite of a module
  and its entry point lays out the same parameters, bindings and entry points as the program linked
  from it, and Slang's reflection JSON is the same text (v2026.21, `CompositeTests`). Borrowed from
  the composite, so it throws once the composite is disposed. `createCompositeComponentType`
  retains each component once itself (measured by reference count); the wrapper takes its own
  reference too, so disposing a component first never strands the composite.
- **Reflection pointers are interior pointers** owned by the `IComponentType` that produced them.
  The binding exposes them only through the borrowed reflection objects, which check the owner on
  every read; the walk (`ReflectionWalker`, in the cooker) reads them through those and nothing
  native leaves it, and the snapshot (`ProgramLayout`) outlives program, session and global session.
  `A_reflection_snapshot_outlives_everything_it_came_from` holds it. The walk's cost is not measured;
  it is a few thousand O(1) getter calls once per shader at cook time.
- **The flat functions are the only way in**: the C++ classes in `slang.h` have no vtable; at
  v2026.14.1 they held 172 inline forwarders, 163 of them direct calls to `spReflection*` and 9 small
  composites (`isArray()`, `getTotalArrayElementCount()`, `unwrapArray()`, ...) (counted by regex
  over the header; re-count at v2026.21). The reflection objects bind the flat functions, not the
  composites; the walk does the composites' arithmetic itself.
- **A declaration cast back is not the same pointer**: `SlangFunction.AsDecl()` then
  `CastToFunction()` reports the same name and parameters through another
  `slang::FunctionReflection*` (v2026.21, `SecondOpinionTests`), so equality of reflection objects
  is pointer identity and a round trip is compared by what it reports.
- **The bindless space is reserved whether or not the code uses it**: an ordinary fragment shader
  reports `getBindlessSpaceIndex` 1 and `IBindlessResourceMetadata::usesBindlessResourceHeap`
  false; one reading through a `DescriptorHandle<Texture2D>` reports a space and true (v2026.21,
  `CoreSurfaceTests`), as `slang.h` describes the two. `ProgramLayout.BindlessSpaceIndex` is the
  reservation.
- **Type names are Slang's canonical spelling**: `float3` is `vector<float,3>`,
  `StructuredBuffer<float4>` is `StructuredBuffer<vector<float,4>, DefaultDataLayout>`
  (`GetFullName`; `GetName` drops the arguments).
- **Overloads are visible only by name**: the declaration tree gives sibling nodes with real
  signatures and `IsOverloaded` false; `FindFunction` gives one function with `IsOverloaded` set and
  an empty signature (`void overloaded()`). Caller's rule: check `IsOverloaded` before `Parameters`.
- **Specializing a generic**: `spReflection_specializeType` on a type from `FindTypeByName` returns
  null with no diagnostics; the working route is the type's generic container through
  `specializeGeneric`, then `GetInnerDecl`, `getTypeFromDecl`, `applySpecializations`. A generic
  function is not in the `FindTypeByName` table and is looked up separately.
  `spReflectionFunction_applySpecializations` leaves the parameters reported as `T`; the
  specialization has to be applied per parameter variable and to the result type. Value generics
  are reachable only this way (`LinkOptions.SpecializationArguments` reports type parameters only).
  `getSpecializedTypeArgCount` is 0 on every path, so arguments are read from `GetFullName`. U15.
- **`specializeGeneric` with a mismatched argument list ends the process**: an `int` where a type
  parameter belongs, or two type arguments for one parameter, access-violates on win-x64 and on
  both Linux legs; osx-arm64 reports `E30060` "expected a type" / "too many arguments" and returns a
  non-null generic alongside the error (v2026.21, prober, all four legs). U3. Handled:
  `SpecializeGeneric` compares the argument kinds and count against the generic before calling.
  Residue: a generic mixing type and value parameters reports them as two lists, so their
  interleaving is not recoverable and a wrong order with matching counts reaches Slang. Patched
  (0004): null with "expected a type" and "too many arguments" on win-x64 and linux-x64 (source
  builds of the tag). The guard stays: the binding also runs on Slang's release payload, which CI
  tests until the switch and `fetch-native.ps1` stages, and which has the defect (Patches).
- **`specializeType` on a non-generic type**: null on win-x64 and osx-arm64, SIGSEGV (exit 139) on
  Linux (v2026.21, prober). U4. Handled: never called in process; `SpecializeGeneric` refuses a
  non-generic type. The cause is undefined behaviour, so the answer is the compiler's: in Release
  `SLANG_ASSERT(x)` is `SLANG_ASSUME(x)` (`source/core/slang-common.h:371`), and the assert of the
  parameter count at `source/slang/slang-check-shader.cpp:4087` lets the optimiser drop the very
  check after it (4088-4089), so the loop reads `specializationParams[0]` of an empty list. The
  same sources built with GCC 13.3 on Ubuntu 24.04 (23be068; that build now needs `-AllowNewerGlibc`)
  return a non-null type: the prober prints `specialized`, exit 0, and
  `Specializing_a_non_generic_type_segfaults_only_on_Linux` fails (742 passed, 14 skipped, 1 failed
  of 757 under WSL, against 743 passed, 14 skipped with the release payload). Patched (0001): null
  and `wrong number of specialization arguments` (38025) from every build;
  `Specializing_a_non_generic_type_is_refused_with_a_diagnostic` holds it, and the release's split
  stays asserted on the release payload. The rest of the handling stays with the release (Patches).
- **Sub-object ranges carry less than their names suggest**: `getSubObjectRangeOffset` returns a
  variable layout with no variable (names come from `getBindingRangeLeafVariable`);
  `getSubObjectRangeSpaceOffset` is 0 for blocks in set 1 and set 2 (U33; patched, 0019, which
  reports 1 and 2; `SecondOpinionTests` asserts each payload's answer), and
  `getBindingRangeDescriptorSetIndex` indexes the enclosing scope's own list. `SubObjectRange`
  therefore carries no space; join on the name against `DescriptorSets`. A `ConstantBuffer<T>` of
  plain values is reported beside parameter blocks, so it is not a `ParameterBlock` detector.
  `SecondOpinionTests.The_calls_that_report_nothing_are_pinned_reporting_nothing` holds the silent
  answers. U15.
- **Append and consume buffers cost two descriptors**: Slang emits a separate storage buffer for
  the count, reported as a binding range named `counter` and absent from `Parameters`; the
  `append-buffers` corpus case declares three buffers and produces five bindings. With an append
  and a consume buffer both counters are named `counter`, and the module names both payloads
  `elements`. Handled: `DescriptorRange.CounterBinding`. Caller's rule: build descriptor set layouts
  from `DescriptorSets`, never from `Parameters`.
- **Loose global uniforms** become a constant buffer nobody declared: null name in the layout,
  `globalParams` in the module (one emitter's invention, so not adopted as a name). Slang reports a
  global-constant-buffer binding of 0 whether or not one exists, so
  `DescriptorRange.IsImplicitGlobalBuffer` is gated on the buffer's size. U15.
- **User attributes**: a type's attributes are asked only of structs; argument values are probed by
  accessor type (no variant to read), with `spReflectionUserAttribute_GetArgumentType` reported
  beside them.
- **Alternate routes agree**: `SecondOpinionTests` requires Slang's second door to each fact
  (parameter binding vs per-category offsets, image format via variable layout vs binding range,
  structural vs laid-out fields, by-name lookups vs enumeration, explicit counter offset vs
  `CounterBinding`) to agree. Weaker than the module, since both answers are Slang's, but separate
  code paths in Slang.
- **Reflection JSON**: `SlangWalkerCorpusTests` compares the walker with
  `spReflection_ToJson` and Slang's own expected results; v2026.21 added four JSON keys, each
  accounted for in the walker's ledger.

### Sizes Slang does not know

- **"Unknown" is a number.** `SLANG_UNKNOWN_SIZE` is `~size_t(0) - 1`, one below
  `SLANG_UNBOUNDED_SIZE`, returned as an ordinary `ulong` by size and offset queries on an array
  whose length is a specialization constant (and on the field after it). Cast to `uint` it is
  `0xFFFFFFFE`; as an offset it points exabytes past the buffer. Handled: `CategorySize.IsKnown`,
  `FieldLayout.IsUniformOffsetKnown`, `ArrayLayout.IsSpecializationSized`; `UnknownSizeTests`.
  Caller's rule: check `IsKnown` / `IsUniformOffsetKnown` before arithmetic.
- **Asking such an array for its element count ends the caller**: `spReflectionType_GetElementCount`
  and `spReflectionType_GetSpecializedElementCount` both crash (win-x64 `SEHException`, Linux abort;
  v2026.21 prober, all four legs), though `slang.h:2633-2642` documents `SLANG_UNKNOWN_SIZE` for
  exactly this case. `slangc -reflection-json` dies the same way on the same shader (0xC0000409,
  v2026.14.1), so it is not the binding's calling. U1. Handled: the walk reads the size marker first
  and never asks; `GetSpecializedElementCount` is called only by the prober. Patched (0002): both
  calls return `SLANG_UNKNOWN_SIZE` (source builds of the tag, win-x64 and linux-x64). The guard
  and the unbound `GetSpecializedElementCount` stay while the binding also runs on Slang's release
  payload (Patches).
- **A resource array sized by a specialization constant cannot be reflected**:
  `Texture2D t[kCount]` makes `spReflectionTypeLayout_getBindingRangeCount` throw
  `Slang::InternalError` through `extern "C"`. win-x64: SEH carries it to the CLR as a catchable
  `SEHException`; linux-x64 and osx-arm64: `std::terminate`, SIGABRT, exit 134 ("terminate called
  after throwing an instance of 'Slang::InternalError'", or `libc++abi: terminating due to uncaught
  exception of type Slang::InternalError`). v2026.21, prober, all four legs. U2. Not guardable: every
  query that does not crash answers exactly as for a fixed-size array. The construct cannot work on
  Vulkan anyway (`descriptorCount` is fixed before specialization). Caller's rule: do not write one;
  a Linux cook farm dies where a Windows workstation loses one shader. Patched (0003): the ranges are
  reported, the array's binding and descriptor counts `SLANG_UNKNOWN_SIZE` (-2 as a `SlangInt`), and
  the walk refuses that count by name with `NotSupportedException`
  (`UnknownSizeTests.A_resource_array_sized_by_a_specialization_constant_is_refused_by_name`) rather
  than reading it as unbounded. On the release the rule above stands (Patches).
- **A buffer whose block holds only such arrays disappears**: `ConstantBuffer<Block>` (and the
  `[[vk::push_constant]]` form) with `struct Block { float4 values[kCount]; }` reports no bindings of
  any kind (v2026.21, `UnknownSizeTests`), and the module dropped the descriptor too while the
  shader reads the buffer (v2026.14.1; re-measure the module half). U5. Handled: the projection
  asserts that every top-level parameter has a binding and refuses by name. Patched (0016): the
  buffer keeps its binding (`UnknownSizeTests.A_buffer_with_no_fixed_size_keeps_its_binding`); the
  refusal stays for the release payload.
- **An unbounded array reports `0xFFFFFFFF`**, which is not a count; normalised to 0 with
  `IsUnbounded` set. Caller's rule: choose the cap.
- **A specialized workgroup dimension reports 0** (`[numthreads(kGroupX, 1, 1)]`), the residue of
  Slang's fix for the access violation in `spReflectionEntryPoint_getComputeThreadGroupSize`
  (shader-slang/slang#8738, fixed by #9245). Handled: `ThreadGroupSize.IsSpecialized`;
  `GroupCountFor` refuses rather than dividing.
- `getBindingRangeImageFormat` on a non-texture range was once recorded as access-violating; at
  v2026.14.1 and v2026.21 it returns `unknown` for every non-texture shape
  (`ProberTests.The_image_format_query_no_longer_crashes_on_any_binding_range_shape`). The guard in
  `ReflectionWalker` stays.

### Layout and the emitted module

- **Matrices are not their components packed**: `float3x3` is 48 bytes (rows on a 16-byte stride), a
  row-major `float4x2` 64. `MatrixLayout.Stride`, `ComponentOffset`. Arrays in a constant buffer
  stride 16 (`float2[3]`).
- **`MatrixLayout.Mode` vs the decoration**: a session set to `ROW_MAJOR` emits members decorated
  `ColMajor`. Same bytes, opposite vocabulary (HLSL rows-by-columns, SPIR-V `OpTypeMatrix` a list of
  columns). Read `Mode` and `Stride`; ignore the decoration.
- **Uniform offsets are per target**: std140 over-aligns a struct member and rounds its size up
  where D3D packing does neither, so a member can sit at byte 32 on Vulkan and 24 on D3D from the
  same source. Slang's own `tests/compute/buffer-layout.slang` shares one expected result across
  five targets by forcing D3D layout on Vulkan; it is the one compute case declared to differ
  (`SlangComputeCorpusTests.ExpectedToDiffer`).
- **A 64-bit 3- or 4-component vertex input takes one location in Slang's numbering**; Vulkan gives
  it two. `float3 position, double4 wide, float2 after` is decorated locations 0, 1, 2, and
  `vkCreateShaderModule` rejects the module (`VUID-StandaloneSpirv-OpEntryPoint-08721`, "conflicting
  input location assignment at location 2"; lavapipe's layers report it under
  `VUID-VkShaderModuleCreateInfo-pCode-08737`). `slangc` alone emits the same. Asserted as wrong at
  v2026.21 by `NriValidationTests.A_wide_64_bit_vertex_attribute_really_does_consume_two_locations`,
  which hands SharpNRI's validated Vulkan device the module alone (NRI has no 64-bit format to
  describe the attribute with), so it runs on lavapipe as well as the RTX 4070 SUPER. U6. Handled:
  NRI's `Format` has no 64-bit vertex format, so the projection refuses a `double` attribute; dxc
  refuses a double in a stage signature. Patched (0014): two locations on GLSL and SPIR-V
  (`NriValidationTests.A_wide_64_bit_vertex_input_is_given_two_locations`); the projection still
  refuses the attribute, for want of an NRI format.
- **`pName` is `main`**: Slang names every per-entry-point module's entry point `main` by default.
  `BakedEntryPoint.ModuleEntryPointName` is read from the module, never derived.
- **The SPIR-V version defaults to 1.5** when unset. A Vulkan 1.1 device accepts at most 1.3 and
  `vkCreateShaderModule` fails with nothing useful. Pin `SpirvVersion`;
  `TargetOptions.VerifyEmittedSpirv` (default on) reads the emitted header and throws on a mismatch.
- **A specialization-constant workgroup size is emitted as `LocalSizeId`**, which needs
  `maintenance4` on the device.
- **`ParameterBlocksUseRegisterSpaces` is inert on SPIR-V**, byte for byte.
- **Fixed upstream at v2026.21, held by tests**: the `sample` interpolation modifier declares
  `SampleRateShading` (v2026.14.1 did not; spirv-val rejected the module), held by
  `ModuleAgreementTests.The_sample_interpolation_modifier_declares_SampleRateShading` (U7); a
  `float4x4` vertex input carries no member `Offset` (v2026.14.1 decorated a `_MatrixStorage`
  member, refused by SDK 1.4.363 as `VUID-StandaloneSpirv-Offset-12509`), held by
  `ModuleAgreementTests.A_matrix_vertex_input_carries_no_member_Offset` (U8). Both read the module,
  so they hold on every leg whatever layer is installed. A device using `sample` must enable
  `sampleRateShading`.

### Compilation, linking and diagnostics

- **A function without `[shader(...)]` is invisible to `FindEntryPoint(name)`** and to
  `Module.EntryPointCount` (0); the overload taking a `SlangStage` reaches it, as
  `slangc -stage fragment -entry main` does.
- **Link-time options: two of the whole range take effect.** `linkWithOptions` accepts every
  `CompilerOptionName` and ignores most. Measured by diffing SPIR-V (v2026.14.1; re-measure):
  Optimization (None 2,052 B, default 1,868, Maximal 1,668) and FloatingPointMode (Precise adds 36 B;
  Fast is the default) work; DebugInformation, VulkanUseEntryPointName (works on the session or
  target) and Capability (`spirv_1_6` still emits 1.5) do nothing. U16. Handled: `LinkTimeOptions`
  has the two typed properties; the rest go through `RawEntries`, and a test asserts a raw entry and
  its typed form emit identical bytes. Patched (0018): VulkanUseEntryPointName and the other
  HLSL-to-Vulkan layout options apply at link time, and Capability or Profile given there warns
  E00136.
- **`GetEntryPointIdentityHash` follows options, not code**: naming the default optimisation level
  explicitly emits identical SPIR-V under a different hash (v2026.21, `LinkOptionsTests`). Fine as a
  conservative cache key, not an answer to "same code"; hash `GetEntryPointCodeBytes` for that.
  v2026.14.1 had the opposite fault (one hash across optimisation levels whose code differed).
- **`isBinaryModuleUpToDate` answers from the session's file cache**: in the session that loaded and
  serialized the module it returns true after the source changed and for a path with no file; a
  fresh session reads disk and returns false for both (v2026.21,
  `The_staleness_check_answers_from_the_sessions_file_cache_not_from_disk`). `slang.h:4790-4797`
  documents true for a primary source that cannot be located, which the fresh session does not
  do. U14. Caller's rule: ask from a session that has not loaded the module. `ReadModuleInfo`
  names the compiler build that wrote a blob; a blob loads only into that build. Patched (0006): the
  check reads the files afresh in any session; the caller's rule stands for the release payload.
- **Severity is parsed from message prefixes**: Slang's diagnostics are text. `SlangDiagnostics.Classify`
  does it once and hands the handler the severity.
- **Type conformances**: without `CreateTypeConformance` an implementation reached only through
  dynamic dispatch is not in the program; registering a type that does not implement the interface
  throws.
- **Link is three calls**: `SlangSession.CreateCompositeComponentType`, `SlangComponentType.Specialize`
  and `.Link` / `.LinkWithOptions`, each throwing with its own operation name and Slang's text
  through the L1 policy; `SlangSession.Link` composes them in Slang's order and emits the same bytes
  (`CompositeTests`). A wrong number of specialization arguments is Slang's `E38025` "wrong number
  of specialization arguments", reported, not a crash.
- **A composite linked twice emits its first link's code**: the second `linkWithOptions` on one
  composite ignores its options (NONE first, then MAXIMAL: the same 1,572 bytes, where a fresh
  composite at MAXIMAL gives 1,188; v2026.21, workstation). U30. Asserted as wrong by
  `CompositeTests`; `SlangSession.Link` composes afresh per call, so it never meets it. Caller's
  rule: one composite per link. Patched (0008): each `linkWithOptions` call gets a component type
  of its own, so the second link's options apply; the rule stands for the release payload.
- **A second module from source at a path the session already holds ends in an internal assert**:
  `loadModuleFromSourceString` of another module name at the same path returns null with
  "assert failure: slang-dictionary.h(325): The key already exists in Dictionary." and no
  diagnostic code (`Linkage::loadParsedModule`'s `Dictionary::add`, `slang-session.cpp:1255`;
  v2026.21, workstation). U31. Asserted as wrong by
  `CompilationTests.A_second_module_from_source_at_the_same_path_ends_in_an_internal_assert`.
  Caller's rule: one path per module from source. Found while measuring the standard modules.
  Patched (0005): E38208 naming the path
  (`CompilationTests.A_second_module_from_source_at_the_same_path_is_diagnosed_naming_the_path`).
- **Specialization constants**: `Pack` refuses a value of the wrong type by name;
  `c.IsFloatingPoint ? c.DefaultFloat : c.DefaultInt` unifies to `double` before boxing and hands
  `Pack` the wrong type whichever branch is taken. A name the shader does not declare throws.

### DXIL

- **No default profile.** A DXIL target names its shader model in `TargetOptions.Profile`, or
  Slang picks: an unprofiled compute shader comes out shader model 6.0, `sm_6_5` named 6.5 (read
  from the DXIL part's program header, v2026.21, `CoreSurfaceTests`). A binding default would be
  one other than the header's (Layers); the tests and tools name `sm_6_5`, the first model with
  mesh shaders and inline ray tracing, which the corpus declares. Registers are per class: `b0`, `t0`, `s0`, `u0` are four bindings at
  index 0 in four categories; NRI's D3D12 backend sorts them by descriptor type, so one projection
  serves both targets.
- `[[vk::binding]]` is ignored on DXIL: a texture at `[[vk::binding(3, 2)]]` lands at the next free
  `t` register of space 0.
- `[vk::push_constant]` is dropped on DXIL (the block is an ordinary constant buffer at a `b`
  register), and reflection keeps no trace of the attribute on either target. U15. Handled:
  `NriProjectionOptions.RootConstantParameters` names the blocks; naming a non-push-constant buffer on
  a SPIR-V layout is refused.
- Specialization constants are lowered to members of an undeclared constant buffer at `b0`; a
  specialization constant in `numthreads` fails with `E55205` "specialization constants not supported
  for numthreads" at v2026.21 (v2026.14.1 compiled the default in).
- dxc refuses `SubpassInput` ("SubpassInput is a Vulkan specific feature") and a double in a stage
  signature ("cannot be used as shader inputs or outputs"); `DxilTests.CannotCompile` lists the
  three refusals with their words.
- A DXIL package carries no `SpirvVersion` and no `WorkgroupSize`; `ModuleEntryPointName` is `main`,
  which D3D12 ignores.
- D3D12 links a vertex stage to a pixel stage by hardware register in declaration order, not by
  location: the harness puts `SV_Position` last in its supplied vertex stages.
- **NRI's viewport origin is top-left on both backends** (`Viewport.originBottomLeft` 0, the
  default): the same clip-space positions land on the same pixels on Vulkan and D3D12, so
  `PixelTests` has one CPU reference, and both backends match it exactly (RTX 4070 SUPER, WARP).

### The other targets

What `TargetValidationTests` measured of Slang's output for the targets without a device here, at
v2026.21 on the workstation (Tests and skips has the counts).

- **GLSL is Vulkan GLSL**: it declares sets and bindings, so it is judged by glslang compiling for
  Vulkan (`-V --target-env vulkan1.2`, Slang's default SPIR-V version's environment); an OpenGL
  compile would refuse it for reasons that are not defects. Tessellation is wrong in two ways the
  SPIR-V target is not: the hull stage's patch-constant function is declared to return its struct
  and ends in `return;` (U18), and the domain stage's per-vertex input is sized by the patch, which
  GLSL forbids (U19). Both patched (0009, 0010). Neither stage declared its layout either
  (`layout(vertices = N) out`, the input primitive), which glslang refuses once the other two are
  fixed (U34, patched, 0022). Behind those the hull stage indexes its per-vertex output with
  `uint(gl_InvocationID)`, which glslang refuses (U35, patched, 0023); with the four, both stages
  are valid GLSL.
- **HLSL** carries Vulkan-only constructs through: `SubpassInput` and a `double` stage input are
  written into the HLSL, and dxc refuses both, as on the DXIL target, where the refusal comes from
  inside Slang's compile instead. Slang's HLSL keeps each entry point's Slang name, so dxc is run
  with `-E` set to it.
- **WGSL**: Slang diagnoses most of what WGSL lacks (`E36107`, `E55202`, `E55205`, `E56105`,
  `E56106`) but not all of it. A `double` ends in an internal error (U23; patched, 0013, E56110);
  `u64` is written although WGSL has none (U25); a `const` is initialised from an `override` (U20;
  patched, 0012); a matrix vertex input sits
  at one `@location` (U21); arrays of textures and samplers are `binding_array`, which naga takes
  only behind its own `enable` (U22, to be confirmed against the specification and Tint). Two
  rejections are naga 30.0.1's and are not called Slang defects: the `immediate_address_space`
  language extension Slang requires for push constants, and WGSL's `subgroups` extension, which
  naga has not implemented.
- **Metal**: the same `double` internal error (U23; patched, E56110), and a mesh shader writing its output per
  member is diagnosed (`E56104`). `xcrun metal` on the macos-15 runner (run 42475073038,
  2026-11-08) refuses five outputs as Slang defects: a texture `read` overload Metal lacks (U26),
  unbounded resource arrays as flexible array members (U27), a matrix vertex input at one
  `[[attribute]]` (U28, U21 on WGSL), and device-pointer arrays as kernel inputs (U29). It also
  refuses `rw-texture-simple` for exceeding Metal's 8 read_write textures, which is Metal's limit.
- **CUDA** source needs two things a consumer must supply: `SLANG_CUDA_ENABLE_HALF` (the prelude's
  own instruction, `slang-cuda-prelude.h:21`) and an architecture NVRTC's default is older than;
  with both, as Slang's own NVRTC path sets them (`compute_75` for NVRTC 12.8 and later), all 56 of
  Slang's compute tests compile. Ray-tracing stages call OptiX, whose header is the OptiX SDK's: the
  five that use it are rejected here, where no OptiX SDK is installed. Rasterization stages end in
  an internal error, `E99999`, not a diagnostic (U23; patched, 0013, the fatal E56111).
- **C++** compiles against Slang's prelude (`prelude/` at the tag, fetched into
  `obj/slang-headers/<version>/prelude/`; the release ships it in `include/`). Half vectors do not
  compile: the prelude defines vector arithmetic and comparison for `float` and `double` only (U24;
  patched, 0011). Rasterization stages end in an internal error (U23; patched, 0013, E56111), and so do
  append and consume buffers, whose atomic counter the emitter has no case for (U32; patched, 0020);
  barriers and atomics are diagnosed (`E36107`).
### Threads

- **A global session and everything made from it belong to one thread at a time**
  (`slang.h:4144-4147`), and sharing one without a lock can be silently wrong. Measured outcomes of
  eight threads on one global session: an access violation in `loadModuleFromSource`, a
  `SlangException` "load module 'x' failed: SLANG_FAIL" on one thread (indistinguishable from a bad
  shader), all eight agreeing with a serial compile, and, on the windows-latest runner in run
  42437636618 (Slang v2026.21), five of eight threads returning success with 1,492 bytes of SPIR-V
  where the serial compile gave 1,436. No outcome holds on every run, so no test pins one; the
  prober's sharing case stays for diagnosis. Handled: the guide's Threads section and its trap row.
  Caller's rule: one global session per thread, or a lock around every use of a shared one.
- **One global session per worker** is the pattern; each output is byte-identical to a serial
  compile (`Threads_with_their_own_global_session_agree_with_a_serial_compile`). Creating one cost
  about 80 ms (v2026.14.1, hardware not recorded; re-measure on the workstation).
- **Back end in parallel after a serialized front end** is supported but marked experimental in
  `slang.h`; `The_back_end_may_be_parallelised_once_the_front_end_has_finished` holds it.
- **`SlangDiagnostics.Policy` and `Handler` are process-global** (Slang's diagnostics are per call,
  with no session to hang a policy on). Set once at startup.

### Pipeline: baking, packages, allocation

- **A baked layout is byte-stable across platforms**: `ProgramLayout.ToJson` writes `\n`
  everywhere. It once used `Environment.NewLine`, and the digests comparison found every layout
  differing between win-x64 and linux-x64.
- **`Bake(program, module)` hashes the shader and everything it imports or includes** (content, not
  timestamps); the string overload hashes one file and leaves a bake claiming to be current after a
  shared module changed.
- `ShaderPackage.ReadFrom` has one failure mode, `InvalidDataException`; `Bake` reads its own output
  back and throws `InvalidOperationException` if it could not (a defect of ours, not the shader's).
  `MalformedInputTests` points at the two readers.
- **Format 5 adds optional sections**: after the entry points, a count and then a name, a length
  and the bytes of each, names unique (refused twice on write and on read). The reader keeps every
  section whole without looking inside, so a package carries a section its reader does not
  understand. Version 4 packages are refused with "Rebake", as every older version is
  (`A_package_of_the_previous_format_says_to_rebake`); none of what format 5 adds is recoverable
  from them, and a cook rebakes cheaply.
- **Allocations.** Once per shader: reading a package parses about 100 KB, `ToNri` allocates about
  5 KB (v2026.14.1, 27cc86b; re-measure). After load, every property, indexer and lookup on the NRI
  projection allocates 0 bytes (`AllocationTests`, `GC.GetAllocatedBytesForCurrentThread`). A compute
  frame driven through an `NriPipelineProjection` allocates 0 bytes over 300 frames after one warm-up
  (b417ede, SharpNRI 191.0.0-beta.4, NRI's NONE backend, win-x64 and linux-x64). Planted: SharpNRI's
  array-returning `AllocateDescriptorSets` costs 40 bytes per set per frame, a `foreach` over
  `DescriptorSets` or `Ranges` 40 per boxed enumerator. Caller's rule: span overloads and indexed
  loops per frame. The projection read back from a package's NRI section (`ReadNriProjection`)
  is the same records and arrays: its lookups allocate 0 bytes and the same NONE frame bound
  through it allocates 0 over 300 frames (branch `sharpslang-bake`, workstation); reading it is
  load-time work, asserted under 64 KB per shader.
- **Zero allocation per frame is default-deny** (the template's rule; branch
  `sharpslang-workflows`). Every public method and computed property of `SharpSlang.Pipeline` and
  `SharpSlang.Pipeline.NRI` counts as per-frame unless it creates an object (`Creates`, 10) or is
  named in `NotPerFrame` with its reason (20: writing, hashing and staleness at bake time, the
  pipeline-interface builders that return a new collection once per pipeline, the declaration
  iterator, the hand-written `ToString`s). `AllocationCoverageTests` reads the IL of the measured
  loops (the `Frame...` local functions of `AllocationTests` and `ProjectedFrame.Run`) and fails
  naming each member none of them calls, and on a name in either list that no longer exists: 38
  members measured, every one at 0 bytes. Measured first, before the fixes: the reader's by-name
  lookups (`ProgramLayout.Parameter`, `EntryPoint`, `SpecializationConstant`, `StructLayout.Field`,
  `ShaderPackage.EntryPoint`) 480 bytes over the six calls of one pass, a LINQ closure and its
  delegate each; `ShaderParameter.DescriptorSet` and `InputAttachmentIndex` 48 bytes each, a
  `foreach` boxing the list's enumerator; `EntryPointLayout.BaseOffset` 80, a closure over the
  category. All are indexed loops now. The LINQ calls without a capture (`PrimaryBinding`,
  `OccupiesDescriptorSlot`, `IsSpecializationConstant`, the uniform offset and size) measured 0 on
  a layout read back from a package, whose lists are `List<T>`. The whole NRI frame runs on a NONE
  device created on NRI's `NriCountingAllocator`: 0 host allocations and 0 reallocations over the
  300 frames, and the two packages declare no P/Invoke and no module reference (from metadata), so
  the host allocations of a frame are SharpNRI's alone. Falsified: a member removed from a loop
  fails naming it (`ProgramLayout.SpecializationConstant(String)`), a planted exclusion for a
  member that does not exist fails naming it, and a LINQ closure planted in
  `NriPipelineProjection.Set` fails both projection loops at 80 bytes.
- **The binding has no per-frame API** (the owner's rule, Rules): every `SharpSlang` call is a Slang
  call that compiles, links, reflects or hands out code, once per shader variant, and the
  reflection objects are read once by the walker into the snapshot (Decisions); the cooker
  (`SharpSlang.Pipeline.Bake`) runs in the asset build. A game that compiles at run time, for a hot
  reload, still compiles once per change.

### NRI projection

- **The engine projects at bake time** (owner, 2026-11-08). `package.WithNriProjection(options)`
  stores the projection as the package's `SharpSlang.Pipeline.NRI/projection` section, read back
  and compared byte for byte before it is returned (as `Bake` checks its layout);
  `package.ReadNriProjection()` builds the same records and desc arrays at load without
  projecting. The section stores the result, not the options, so a game needs no projection rules
  and no options. It records `NriHeaders.Version` and refuses a section written against another
  (`InvalidDataException`, "Rebake"): the enum values and struct fields are SharpNRI.Descs'.
  Measured: on all 33 corpus shaders, compiled to SPIR-V and to DXIL, what is read back equals a
  fresh `ToNri` field by field, every public field of every desc struct compared by reflection, and
  a shader the projection refuses is refused at bake time with the same words (`NriPackageTests`);
  a pipeline built from the loaded descs dispatches correctly on validated Vulkan and D3D12
  (`NriDeviceTests`), and the pixel test renders through them on both backends.
- Rules read from NRI v191's Vulkan backend (`PipelineLayoutVK.hpp`); `NriProjectionTests` pins the
  NRI version every reading reports. On an NRI major bump, re-read the four rules it names.
- **`SetIndex` is not the register space**: NRI indexes sets by position in the desc; SPIR-V by
  `set = N`. They differ once a space is skipped; NRI's Vulkan backend places each set at its
  register space and fills gaps with empty layouts.
- **An unbounded array needs a cap**: `descriptorNum` has no "unbounded"; `ToNri` refuses without
  `UnboundedArrayCap` and returns `ARRAY | PARTIALLY_BOUND`. `VARIABLE_SIZED_ARRAY` is legal only on
  a set's last binding, which Slang does not arrange (`descriptor-arrays`: the unbounded array is
  binding 1, a sampler binding 2).
- **`ARRAY` on every array range is load-bearing**: without it NRI's Vulkan backend reads
  `descriptorNum` consecutive one-descriptor bindings (the D3D register-range reading).
- **`VkBindingOffsets` must be zero**: NRI adds per-class shifts Slang was not told about; the
  projection refuses non-zero offsets.
- Refused with the construct named: combined texture samplers, inline uniform blocks, 64-bit or
  three-component half vertex attributes, a second push-constant block. NRI has no specialization
  constants: specialize at link time.
- `STRUCTURED_BUFFER` / `STORAGE_STRUCTURED_BUFFER` and `BUFFER` / `STORAGE_BUFFER` tell an SRV from a
  UAV on D3D12; on Vulkan each pair is one descriptor type.
- **The Descs pin must match SharpNRI's own**: SharpNRI 191.0.0-beta.4 depends on exactly
  `SharpNRI.Descs` 191.0.0-beta.1. A different Descs pin does not fail the restore: measured with
  1.0.0-beta.2, the tests' restore warned NU1608 and resolved SharpNRI's Descs for the tests while the
  projection built against the pin. CI's `-warnaserror` makes the warning the error.
- The pins are named `SharpNri*PackageVersion`, not `SharpNRIVersion`: MSBuild property names ignore
  case, and SharpNRI's own build files define `SharpNRI*` properties.
- **NRI moves only the first slice of a 3D storage texture** (a third-party defect, excused and
  recorded, not patched). On the RTX 4070 SUPER with SharpNRI 191.0.0-beta.4 (NRI v191) and the
  1.4.363 layer, the compute corpus case `rw-texture-simple` draws `VUID-vkCmdDraw-None-09600` for
  `arrayLayer` 1, 2 and 3 of each of its three 4x4x4 `RWTexture3D`s ("expects ... to be in layout
  VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL--instead, current layout is VK_IMAGE_LAYOUT_UNDEFINED"), nine
  errors, nothing about slice 0. NRI creates 3D textures `VK_IMAGE_CREATE_2D_ARRAY_COMPATIBLE_BIT`
  ("allow 3D demotion to a set of layers", `DeviceVK.hpp`) and enables `VK_KHR_maintenance9` where
  the device has it, under which a 3D image's barrier range names slices, and gives a 3D texture's
  barrier `layerCount = TextureDesc.layerNum`, 1 (`CommandBufferVK.hpp`), so its upload helper moves
  slice 0 alone. The readback still matches Slang's recorded words; lavapipe with the same layer
  reports none. Handled: `SlangComputeCorpusTests.IsNriThreeDimensionalSliceLayout` excuses that VUID
  only for a slice index above 0, so the same VUID about anything else fails. A report belongs to
  NRI, through SharpNRI.

### Cross-platform behaviour

- **x64 and arm64 emit different SPIR-V for `SV_VertexID`**: win-x64 and linux-x64 are
  byte-identical, x64 and aarch64 differ on exactly the three corpus shaders that use it
  (`stage-narrowing`, `system-values`, `vertex-interface`). Nothing is renumbered: Slang creates the
  two builtins it lowers `SV_VertexID` to, `VertexIndex` and `BaseVertex`, in opposite orders, so
  which ID carries which `BuiltIn` swaps, the pair swaps places in the `OpEntryPoint` interface, and
  the operands of the `OpISub` computing `VertexIndex - BaseVertex` swap with them. Equivalent, never
  equal. U17. Handled: `tools/ci/cross-arch-differences.txt` is checked in both directions by
  `compare-digests.sh` (a new difference fails, a vanished one fails); `spirv-worddiff.py` reports
  every differing word. Holds at v2026.21 (run 42423571989, four legs). Caller's rule: cook on one
  architecture or content-address per architecture. Patched (0021): the cause is the evaluation
  order of two loads written as the arguments of one call, which the compilers choose differently;
  emitted in source order, win-x64 numbers `VertexIndex` before `BaseVertex` as aarch64 did
  (`SpirvDigestTests`, both payloads). `compare-digests.sh` expects no difference when both
  architectures' payloads carry 0021 (each leg's `payload-patches.txt`); that the patched modules
  are equal across architectures is first measured by CI's source build.
- **Crash behaviour has no platform rule**: the resource-array `InternalError` is catchable on
  Windows and fatal on Linux and macOS; `specializeType` on a non-generic type is null on Windows
  and macOS and fatal on Linux; `specializeGeneric` mismatches crash on Windows and Linux and are
  diagnosed on macOS. Each call is asked on every leg.

### Allocator poisoning and crash diagnosis

- The Test step sets `MALLOC_PERTURB_=165`, `GLIBC_TUNABLES=glibc.malloc.tcache_count=0`,
  `MallocScribble=1`, `MallocPreScribble=1`, `MallocNanoZone=0` on every leg (each OS ignores the
  others'). A use-after-free then reads `0xa5a5...` (non-canonical on x86-64, a fault when
  dereferenced) instead of stale intact data.
- `MALLOC_PERTURB_` alone poisoned a 4 KB block and left a 64 B block untouched (glibc's `_int_free`
  returns through the tcache before `free_perturb`); disabling the tcache arms both and costs about
  6 % on a compile-heavy workload (linux-x64, v2026.14.1).
- `MALLOC_CHECK_=3` is absent on purpose: glibc 2.34 moved that checking into `libc_malloc_debug.so.0`,
  so on glibc 2.39 it is a no-op unless preloaded, and with the debug allocator preloaded a one-chunk
  overflow that plain glibc aborts on ran to exit 0.
- macOS zeroes freed 64-byte blocks with no variable set; `MallocScribble` (`0x55`) is what poisons
  the 4 KB block, `MallocPreScribble` (`0xAA`) reaches fresh small blocks once `MallocNanoZone=0`.
  `The_allocator_poisoning_is_armed_and_reaches_small_allocations` asserts all four bytes at both
  sizes on every leg.
- On a failed leg CI prints the test the diagnostic log shows started and never finished, the last
  15 completed tests and a tally of
  completed tests per class;
  on osx-arm64 `tools/ci/macos-backtrace.sh` reads the `.ips` crash report and reruns the prober's
  teardown under `lldb`. A test-host crash's reported "reason" is stderr, never the cause.

### Actions budget

The repository is private on GitHub's Free plan: $12 of Actions a month, which is 2,000 Linux
minutes at $0.006, with Windows at $0.010 and macOS at $0.062 a minute, each job rounded up to whole
minutes. October 2026's allowance went in two days, a third of the runs were repeats on `main` of
code its branch had just passed, and macOS was 57 % of the money. The rules since 2026-11-07 are the
owner's (owner, 2026-11-07):

- **Nothing starts by itself on a branch.** A branch is tested by Actions > CI > Run workflow on it.
  Such a run does not appear among a pull request's checks, so the gate marks a pending commit
  status named "ci" and the `report` job posts the outcome (skipped by the gate counts as passed;
  any other non-success, or a failed gate, fails it).
- **A branch must be up to date with `master` and have a green run before it merges.** GitHub cannot
  enforce either on a private Free repository, so the gate refuses a branch behind `master`, and "ci"
  is what a ruleset will require once the repository is public.
- **Nothing re-runs on `master` unless the tree differs from what a branch run tested**
  (`tools/ci/ci-gate.ps1`; a job counts as done for a tree when a run of `ci.yml`, `checks.yml` or
  `regen.yml` of a commit with that tree succeeded it, matched by the job's own name, so `lint` in
  `checks.yml` and `checks / lint` in `ci.yml` are one job). Pushes changing only Markdown or
  `docs/` start nothing on `master`. Run read-only against history (branch `sharpslang-workflows`):
  the push of f67ee8c skips the legs, docs and lint and runs zero-alloc, which no run has passed;
  the merged `sharpslang-packaging` head is refused as one commit behind `master`.
- **Never two overlapping runs on one head**: `ci.yml`'s gate fails while a `checks.yml` run is
  queued or in progress on the commit, and the other way round (the template's rule).
- **macOS on demand and weekly**: the `macos` input of a manual run, and a schedule (Monday 06:00
  UTC) that runs the `osx-arm64` leg alone on `master`, skipped when the tree already passed it.
  Nothing in a release waits for macOS (owner, 2026-11-08).
- **The workflows** (the template's set). Timeouts are a few times the slowest successful run of
  2026-11-07/08 (24 runs of `ci.yml`, read from the Actions API with the GCM token):

  | Workflow | Starts on | Jobs (timeout, minutes; slowest measured) |
  |---|---|---|
  | `ci.yml` | `master` push (not docs-only), manual, weekly | `gate` (5; 46 s), `regen` (calls `regen.yml` on a branch whose inputs changed), `checks` (calls `checks.yml`), `docs` (5; 11 s), `test` per leg (win-x64 30; 521 s, linux-x64 35; 667 s, linux-arm64 20; 360 s, osx-arm64 25; 474 s; the Test step 20; 375 s), `native-from-source` (off until `SHARPSLANG_NATIVE_FROM_SOURCE` is `true`, then the legs need it; 120, unmeasured), `digests` (5; 9 s, the leg count in its name because the gate reads it back), `report` (5; 16 s) |
  | `checks.yml` | manual; called by `ci.yml` | `gate` (5), `lint` (10; 83 s before the descs version), `zero-alloc` (10; unmeasured on a runner) |
  | `regen.yml` | `master` push touching its inputs, manual; called by `ci.yml` | `gate` (5), `generated bindings are current` (10; 43 s) |
  | `coverage.yml` | `master` push touching a measured input or the report, manual | `coverage.ps1 -Check` (5; git only). Red blocks nothing |
  | `release.yml` | manual, `master` only | version, native, pack, consume, release, osx-arm64, nuget (The release, below) |

- **"ci" covers the run.** The report job's status fails on any job of the run that neither passed
  nor was skipped by the gate, `regen` and `checks` included, so a green "ci" means the generator,
  lint, zero-alloc, docs and every requested leg passed for the tree, here or in an earlier run.
- **The payload cache** (the template's): `.github/actions/slang-payload` stages `runtimes/<rid>/`
  from the cache, or on a miss from Slang's release (`source: release`, what CI stages until the
  repository is public) or from the submodule (`source: build`, the release and later CI), and
  saves it right after, before any build or test. The key is `tools/ci/native-payload-key.ps1`:
  the git object ids of the props, `THIRD-PARTY-NOTICES.md`, the action itself (the workflow that
  makes the payload) and either `tools/fetch-native.ps1` or the `slang` pointer, `patches/` and
  `tools/build-native.ps1`; the same on every OS, and the same in a test leg, the zero-alloc job and
  the release, so a payload is made once per input set. A build also keeps its symbols in the cache
  (`obj/native-symbols/<rid>/`). Other caches: the header and corpus per `Directory.Build.props`
  hash, the 1.4.363 layer per version, naga per version.
- **What a run costs**, at the measured times, billed per job rounded up: a full branch run of
  three legs is about 26 Linux and 9 Windows minutes, $0.25 ($0.02 of it the new zero-alloc job);
  the osx-arm64 leg 8 minutes, $0.50. The weekly run costs that when `master`'s tree changed since
  macOS last passed, at most about $2.15 a month (18 % of $12), and a gate minute otherwise; a
  manual macOS run costs the same again.

- Never push what starts a run known to fail, and never start two overlapping runs on one head. The
  remaining allowance cannot be read with the available token (the billing endpoint answers 404).
