# Corpus shaders whose emitted SPIR-V differs between x86-64 and aarch64.
#
# Not expected values — expected *disagreements*. A golden file of digests would go stale on every
# Slang bump and get regenerated whenever it was inconvenient; this list is checked in both
# directions, so a new disagreement fails and so does an old one that has gone away. Upstream fixing
# one of these is a failing test rather than silence.
#
# Found by the digests job on its first real run. The layout half agrees on all four legs, and the
# module half agrees between operating systems — win-x64 and linux-x64 are byte-identical — so this
# is an architecture split in Slang's own code generation, not an OS one and not ours. §9.33.
#
# The correlation is exact: SV_VertexID appears in exactly these three corpus shaders, and exactly
# these three disagree. Nothing uses it without disagreeing and nothing disagrees without using it.
#
# The mechanism, from disassembling both sides (§9.38): nothing is renumbered, which is what §9.34
# guessed. The IDs are the same. Slang creates the two builtin inputs that SV_VertexID lowers to —
# VertexIndex and BaseVertex — in the opposite order on the two architectures, so which ID carries
# which BuiltIn swaps, the pair swaps places in the OpEntryPoint interface list, and the operands of
# the OpISub computing `VertexIndex - BaseVertex` swap with them. Every difference is one of those
# three, in matched pairs. Both modules compute the same thing.
#
# Equivalent, then, but not identical, and not identical in a way any canonicalizer would fix — the
# emission order is upstream's and there is nothing here to change.
#
# What it means for a cook farm: assets are reproducible on a fleet of one architecture, and are not
# byte-comparable across a mixed one. Cook on one architecture, or content-address per architecture.
#
#   <shader name>    <reason>

stage-narrowing     SV_VertexID on the vertex entry point
system-values       SV_VertexID and SV_InstanceID in the vertex input struct
vertex-interface    SV_VertexID in the vertex input struct
